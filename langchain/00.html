学ぶ理由と、身につくこと

🟣 なぜ学ぶ価値があるのか

  • LLMは「何でも文章で答える」ように見えて、計算が苦手だったり間違いを言ったりする。その仕組みと限界を知らないと、信頼できないアプリを作ってしまうから。
  • 指示文の工夫ひとつで出力が劇的に変わる。書き方を知らないと、LLMの力を引き出せないから。
  • LLM単体では「役に立つアプリ」にならない。外部の道具・知識と組み合わせる発想（＝LangChainの根っこ）が必要だから。

🟢 これを知ったらできるようになること

  • LLM・チャットモデル・トークン・プロンプトといった基本用語を、初めての人に説明できるようになる。
  • Zero-shot・CoT・RAG・ツール呼び出し・Few-shotという5つの書き方を使い分けられるようになる。
  • LangChainが「何をまとめて、何を組み合わせやすくしてくれるか」を理解し、本書全体の地図を持てるようになる。

きっかけ：LLMは計算ができない

ソラ
ソラなるほど。LangChainはどういうきっかけで生まれたんですか？
リク
リク2022年10月22日、Harrison Chaseという人がLangChainの最初のコミットをGitHubに公開した。きっかけは「本当に有用なLLMアプリを作るには、LLMを他の計算リソースや知識ソースと組み合わせる必要がある」という気づきだ。例を見せよう。

次のコードは、LLMに割り算のあまりを直接たずねる指示文を用意し、そのまま渡したときに何が返るかを示しています。

コードを見る（1行ずつ説明つき）
# LLMに計算をそのまま尋ねる文章を、変数 prompt に入れておく。
prompt = "1,234個のボールを123人で均等に分けたとき、ボールはいくつ余りますか？"

# 用意した文章をLLMに渡して、返ってきた答えを画面に出す。
# LLMは数を1つずつ数えているわけではなく「次に来そうな文字」を選んでいるだけなので、
# 計算の答えは高い確率でずれる。
print(llm.invoke(prompt))
# --- 実行結果 ---
# 余りは 10 個です。   ← 正しくは 4。LLMは計算が苦手で、もっともらしい数を書いてしまう

そこで発想を変えます。LLMには「計算そのもの」ではなく「計算式に書き直すこと」だけをやらせて、計算はPythonにさせます。

コードを見る（1行ずつ説明つき）
# LLMには答えではなく「電卓が読める式に書き直したもの」だけを出してもらう指示文を用意する。
prompt = "次の質問を、余りを求める計算式だけに書き直してください: 1,234個のボールを123人で均等に分けたとき、余りは？"

# LLMに渡して、返ってきた式の文字列を受け取る。ここまでは文章を作る仕事なのでLLMが得意。
expression = llm.invoke(prompt)

# 受け取った式を画面に出して、想定どおりの形になっているか確認する。
print(expression)
# --- 実行結果 ---
# 1234 % 123

# 計算はLLMではなくPythonにやらせる。% は「割ったあまり」を求める記号。
# 1234 を 123 で割ると 10 回分けられて 4 個あまるので、答えは 4 になる。
print(1234 % 123)
# --- 実行結果 ---
# 4   ← こちらは必ず正しい

🔎 具体例：同じ質問で結果がどう変わるか

「1,234個のボールを123人で均等に分けたときの余りは？」という質問を、LLMにそのまま聞くと 10 や 7 など毎回ちがう数が返ってきて、しかも正しくありません。一方、LLMには「1234 % 123」という式に書き直させるだけにして、その式をPythonに計算させると、答えは必ず 4 になります。

LLMがやったのは「日本語を式の形に直す」という文章の仕事だけ。数を正確に扱う仕事は、それが得意なプログラムに渡しています。

「大規模」＋「言語モデル」に分けて読む

📦

「大規模」の意味

学習に使った文章の量と、モデルの中のパラメータの数がとても多いこと。GPT-3は1,750億個のパラメータを持ち、45TBの文章で学習されています。パラメータは、各ニューロンの出力や、隣のニューロンとのつながりの強さを決める数値です。

🔤

「言語モデル」の意味

文章を受け取って文章を返す手順のこと。ニューラルネットワーク——単純な数学の関数（ニューロン）を無数につなぎ、その出力と結びつきの総和で最終出力を決める機械学習モデル——の一種です。

学習データに英語が多いことの影響

ソラ
ソラ学習データって、英語が多いんですか？
リク
リク鋭い。学習データに英語が多いから、ほとんどのモデルは英語が得意だ。ここで「得意」とは「英語で望む出力を得やすい」という意味。BLOOMみたいに多言語を狙ったモデルもある。面白いのは、主に英語で学習したLLMでも、言語ごとの性能差は思ったほど大きくないこと。覚えた意味の理解を、他の言語にも部分的に持ち込めると報告されている。

トークン ― 処理と料金の単位

次のコードは、英語の文が実際に何個のトークンに分かれるかを数えています（GPT-4o miniの切り分け方の例）。

コードを見る（1行ずつ説明つき）
# 文章をトークンに切り分ける道具を読み込む。
import tiktoken

# GPT-4o mini が使っている切り分け方を選ぶ。モデルごとに切り方が違う。
enc = tiktoken.encoding_for_model("gpt-4o-mini")

# 英語の文を用意する。ここは英語の切り分けを見せる例なので英語のままにする。
text = "Good morning dearest friend"

# 文章をトークンの番号（ID）の並びに変換する。番号1個が1トークン。
tokens = enc.encode(text)

# 何個に分かれたかを数えて出す。よく出る語は1個に、めずらしい語は複数に分かれる。
print(len(tokens))
# --- 実行結果 ---
# 5

# どの文字のかたまりが何番になったかを、1個ずつ並べて確認する。
# "dearest" はめずらしい語なので "de" と "arest" の2個に割られている。
for t in tokens:
    print(enc.decode([t]), t)
# --- 実行結果 ---
# Good 30744
#  morning 8709
#  de 334

英語では1トークンが平均4文字ほど、つまり単語のおよそ4分の3にあたります。「good morning dearest friend」（26文字）は5トークン。よく出てくる「morning」は1個にまとまり、めずらしい「dearest」は「de」＋「arest」の2個に割れます。

第1問LLMとは

❓ LLM（大規模言語モデル）とは何ですか。初めて聞く人に説明してください。

✅ 解答例
LLMは、テキストを入力すると、人間のように続きのテキストを予測して生成するよう、膨大なデータで学習された巨大な機械学習モデル。スマホの文字入力で次の言葉の候補が出るのと同じ「次に来る語を当てる」仕組みを、けた違いの規模でやっているもの。仕組みとしては、前の単語列を踏まえて、次に来るトークン（テキストの最小のかたまり）の確率を推定している。中心技術はトランスフォーマーで、文中の各単語を他のすべての単語との関係で捉えて前後のつながりを理解する。
📝 採点ポイント
□ テキストを入れると続きを予測・生成する、に触れている
□ 次に来る語を当てる仕組みという説明ができている
□ トークン単位の確率予測やトランスフォーマーに触れている
第2問チャットモデルの役割

❓ チャットモデルで使われる system / user / assistant の3つの役割（ロール）は、それぞれ何を表しますか。

✅ 解答例
systemは仕事の指示や枠組み（「あなたは親切なアシスタントです」など）、userは実際の質問や依頼（利用者の入力）、assistantはモデルの返答を表す。この役割分けによって、モデルの出力を調整しやすくなり、利用者の入力を事前の指示と混同しにくくなる（ジェイルブレイクを起きにくくする）効果もある。
📝 採点ポイント
□ system＝指示・枠組み、user＝質問、assistant＝返答、を区別できている
□ 出力を調整しやすくする役割に触れている
□ ジェイルブレイクを防ぐ効果に触れている（できれば）
第3問プロンプトの使い分け

❓ Zero-shot・CoT・RAG・ツール呼び出しの4つを挙げ、クーリッジ大統領の年齢を求める例で、なぜ単体ではうまくいかず、組み合わせると正解できたのかを説明してください。

✅ 解答例
Zero-shotはそのまま質問する方法で、単純な質問には効くが、この問題では不正確だった。CoTは「ステップバイステップで考えて」と促す方法で、考え方は良くなったが知識（義母の生没年）を誤った。RAGは正しい事実をコンテキストとして添える方法で、知識は正しくなったが、LLMは計算が苦手で引き算を3年間違えた。ツール呼び出しは電卓などの外部の機能を使わせる方法。これらを組み合わせ、RAGで正しい事実を渡し、CoTで段階的に考えさせ、ツール呼び出しで電卓に 1929 - 1872 を計算させることで、正解の57歳が得られた。
📝 採点ポイント
□ 4つのやり方をそれぞれ説明している
□ 単体での失敗（知識の誤り・計算の苦手さ）に触れている
□ 組み合わせ（RAG＋CoT＋ツール呼び出し）で正解した、に触れている
第4問なぜLLMを道具と組み合わせるのか

❓ LangChainが生まれたきっかけである「LLMを他の計算リソースや知識ソースと組み合わせる」という考えを、ボールの計算や電卓の例で説明してください。

✅ 解答例
LLMは計算が苦手なので、「1,234個のボールを123人で均等に分けたときの余りは？」のような問題をそのまま聞くと、がっかりする答えしか返らない。でも電卓の機能と組み合わせれば、LLMに「質問を電卓が扱える式（1234 % 123）に書き換えて」と指示し、その出力を電卓の関数に渡すことで正確な答え（4）が得られる。このように、LLM単体ではなく外部の道具や知識と組み合わせてこそ本当に役立つアプリになる、という気づきがLangChain誕生の動機。
📝 採点ポイント
□ LLMは計算が苦手という前提に触れている
□ 電卓など外部の道具に処理を渡す、に触れている
□ LLM単体でなく組み合わせてこそ役立つ、というLangChainの動機に触れている
