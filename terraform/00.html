暗黒時代から Terraform へ（プロローグ）

Terraform って何者？ なぜ生まれた？

要するに：Terraform は、手作業だった街づくり（インフラ構築）を「設計図＝コード」にして自動化する、HashiCorp 製のオープンソースの道具。短い文章でいろんなクラウドに街を建てられます。

ハル
ハル棟梁、はじめまして！ 今日からお世話になります。この「グラウンドワークス工房」って、何を作る工房なんですか？
棟梁
棟梁ようこそハル。うちはな、クラウドという広い土地の上に「街」を建てる工房だ。サーバやデータベースやネットワークといった設備を組み合わせて、ひとつの動く街を作るのが仕事だよ。
ハル
ハル街…ですか。でも昔の人はどうやって街を建てていたんですか？
棟梁
棟梁昔はな、「システム管理者」と呼ばれる職人たちが、すべてを手作業でやっていた。一本の道、一軒の家、一つの井戸、配線の一本一本まで全部その人の手で置いていた。腕は確かだが、これは恐怖に満ちた暗黒の時代だったんだよ。
ハル
ハル恐怖、ですか？ 手作業ってむしろ丁寧そうですけど。
棟梁
棟梁そこが落とし穴でな。手作業には四つの恐怖がついて回った。下の四枚の札を見てくれ。

手作業時代の四つの恐怖

🛑

① 街が止まる恐怖

うっかり操作で街全体が動かなくなる（ダウンタイム）。

🧩

② 置き間違いの恐怖

手作業ゆえの設定ミス。一箇所ずれると街が傾く。

🐢

③ 遅くて壊れやすい恐怖

街を広げる作業が遅く、途中で崩れやすい。

🚪

④ 属人化の恐怖

その職人が休暇で街を離れた途端、誰も作り方を知らなくなる。

ハル
ハルうわぁ…一人の頭の中だけに街の作り方が入ってるのは怖いですね。
棟梁
棟梁そこで現れたのが Terraform という新しい道具だ。DevOps の流れの中で生まれた。これを使うと、街の作り方を「文章＝設計図」として書き残せる。書いた設計図を渡せば、誰でも、何度でも、同じ街を建て直せるんだ。
棟梁
棟梁Terraform は HashiCorp という会社が作った、誰でも無料で使えるオープンソースの道具だ。宣言型の、やさしい言葉で街を定義できる。しかも一つの道具で、AWS・Microsoft Azure・Google Cloud Platform・DigitalOcean といった色々なクラウド、自社専用の土地（プライベートクラウド）、OpenStack や VMware のような仮想の土地まで、またいで街を建てられるんだ。
ハル
ハル設計図を書くって、具体的にはどんな感じなんですか？
棟梁
棟梁例えば AWS という土地に建物（サーバ）を一棟だけ建てるなら、こういう設計図を書く。今は中身を全部わからなくていい。「これくらい短い文章で街が建つ」という雰囲気だけ感じてくれ。

🏙️ たとえ話：設計図ひとつで街が建つ

昔の職人は、街の一軒一軒を自分の手で組み立てていました。だから職人が一人いなくなると、街の建て方も一緒に消えてしまったのです。Terraform は「街の作り方を一枚の設計図に書いておく道具」。設計図さえあれば、別の人でも、明日でも、十年後でも、まったく同じ街を建て直せます。

▼ 下のコードは「AWS という土地に建物（サーバ）を1棟だけ建てる設計図」です。短い文章で街が建つ雰囲気だけ感じればOKです。

設計図の例（HCL）を見る 
# このTerraformコードは、AWSという土地に建物(サーバ)を1棟だけ建てる設計図
# terraform ブロック … この設計図が必要とする道具とそのバージョンの取り決め
# provider "aws" … どの土地(クラウド)で作業するかの指定
# resource "aws_instance" … 実際に建てる建材(ここでは1棟の建物=サーバ)

terraform {
  required_version = ">= 1.0.0, < 2.0.0"  # ① Terraform本体のバージョン1系で使う約束

  required_providers {
    aws = {
      source  = "hashicorp/aws"  # ② AWSという土地を扱う専用道具の入手元
      version = "~> 4.0"          # ③ その道具はバージョン4系を使う
    }
  }
}

provider "aws" {
  region = "us-east-2"  # ④ 「us-east-2」という地域(リージョン)に街を建てる
}

resource "aws_instance" "example" {
  ami           = "ami-0fb653ca2d3203ac1"  # ⑤ 建物の元になる設計の型番(どんなOSか)
  instance_type = "t2.micro"               # ⑥ 建物の大きさ(一番小さいお試しサイズ)
}
棟梁
棟梁そしてこの設計図を現実の土地に建てるには、たった二つの号令をかけるだけだ。

▼ 下のコードは「設計図を実際の街に建てる2つの号令」です。準備と建設の二段階です。

2つの号令（ターミナル）を見る 
# 上の設計図を実際の街に建てる2つの号令
terraform init    # 必要な道具(プロバイダ)を取り寄せる準備の号令
terraform apply   # 設計図どおりに実際に街を建てる号令
ハル
ハルたった二行で建物が建つんですか！？ ブラウザでポチポチ画面をクリックしなくていいんだ…！
棟梁
棟梁そうだ。このシンプルさと力強さのおかげで Terraform は DevOps の世界の中心になった。自動テスト・継続的インテグレーション・継続的デリバリ、それに Docker・Chef・Puppet といった他の道具とも手を組める。退屈で壊れやすく手作業だらけだった街づくりを、頑丈で自動化された土台に置き換えられるんだよ。
ハル
ハルなるほど、つまり「街の作り方を文章にして自動化する道具」が Terraform ってことですね！
棟梁
棟梁その通り。この本を通して、一番小さな「こんにちは世界（Hello World）」の街から、大勢の住人（トラフィック）と大勢の職人（開発者）を支える本格的な街——仮想の建物・Kubernetes という建物群の管理人・Docker という箱・交通整理係（ロードバランサ）・記録倉庫（データベース）まで——を、ほんの数章で建てていく。読み終わる頃には、本番の街を建てる準備が整っているはずだ。

🤔 なぜこれが必要か / これを知ると何ができる？

  • 手作業の街づくりには「止まる・間違える・遅い・属人化する」四つの恐怖があり、それを解決するため。
  • 設計図として残せば、誰でも・何度でも・同じ街を再現できるようになる。
  • Terraform の正体と立ち位置（DevOps の中心道具）を一言で説明できるようになる。

📌 この項のまとめ

  • 昔の街づくりは手作業で、四つの恐怖（ダウンタイム・設定ミス・遅さ・属人化）があった。
  • Terraform は HashiCorp 製・オープンソース・宣言型で、複数のクラウドに対応する。
  • 街は短い設計図（コード）で定義し、terraform init と terraform apply の二つの号令で建てる。
  • この本は最小の例から本番レベルの本格的な街まで、数章で導いてくれる。

この本を書いた理由

なぜ公式説明書だけでは足りないのか

要するに：Terraform は強力だが「成熟（パターン・ベストプラクティス・テスト・チーム運用の知見）」が足りませんでした。本書はその穴を埋めます。ただし読むだけでなく、実際に手を動かすことが上達の条件です。

ハル
ハルTerraform がそんなにいい道具なら、わざわざ本にしなくても、みんなすぐ使いこなせそうですけど…なぜこの本が必要だったんですか？
棟梁
棟梁いい疑問だ。Terraform は強力で、ほとんどのクラウドで使えて、言葉はきれいでシンプル、設計図の再利用・テスト・版の管理（バージョン管理）もできる。オープンソースで、親切で活発な仲間（コミュニティ）もいる。だが一つだけ足りないものがあった。それは「成熟」だ。
ハル
ハル成熟が足りない、ってどういうことですか？
棟梁
棟梁Terraform はとても人気者になったが、まだ比較的新しい道具なんだ。だから、達人になる手助けをしてくれる本・記事・先生を探すのがまだ難しい。公式の説明書（ドキュメント）は、基本の文法や機能を知るには役立つ。だが、独特の型（パターン）、ベストプラクティス、テスト、再利用、チームでの進め方は、ほとんど書かれていない。
ハル
ハル説明書はあるのに、足りないんですか？
棟梁
棟梁たとえるなら、フランス語をうまく話したいのに、単語ばかり覚えて文法も言い回しも学ばないようなものだ。それでは会話にならない。
棟梁
棟梁著者はな、開発者が Terraform を使いこなせるよう手助けしたくて、この本を書いた。彼は Terraform が生まれて七年のうち六年、自分の会社 Gruntwork で使い続けてきた。Gruntwork では、たくさんの会社の本番で鍛えられた、三十万行を超える再利用できるインフラ設計図のライブラリを作る、中心の道具として Terraform を使っている。
ハル
ハル三十万行…！ それだけ使えば、いろんな失敗も知っていそうですね。
棟梁
棟梁その通り。大きなインフラ設計図を何年も書き、保守し、いろんな会社・いろんな使い方で使ってきたからこそ、たくさんの「痛い学び」があった。著者の狙いは、その学びを君たちに分けて、長い回り道を短くし、数日で Terraform を使えるようにすることだ。
ハル
ハルじゃあ、この本を読めばもう達人ですね！
棟梁
棟梁惜しい、そこが落とし穴だ。本を読んだだけでは使いこなせるようにならない。フランス語を流暢にしたければ、ネイティブと話し、番組を見て、歌を聞く必要がある。Terraform も同じで、実際にコードを書き、本物のソフトを管理し、本物のサーバに建てて初めて身につく。だから——コードを読み、書き、走らせる準備をしておこう。

自分の言葉で答えてみよう（全5問）

第1問Terraform とは何か

Terraform はどんな道具で、何のために使うのか、身近なたとえを交えて説明してみてください。

✅ 解答例を見る
Terraform は、サーバやデータベースなどのインフラ（街の設備）を「設計図＝コード」として書き、その設計図から自動で構築・管理できる道具です。手作業で一つずつ設定する代わりに、文章で完成形を書いて号令をかけるだけで、誰でも何度でも同じ環境を再現できます。HashiCorp が作ったオープンソースで、複数のクラウドに対応します。
📝 採点ポイントを見る
□ インフラを「コード（設計図）」として書く道具だと述べている
□ 手作業の自動化・再現性のメリットに触れている
□ オープンソースで複数クラウド対応である点に触れている
第2問手作業時代の問題点

Terraform 以前の「手作業で街を建てていた時代」には、どんな恐怖（問題）があったか挙げてみてください。

✅ 解答例を見る
手作業の時代には、街が止まってしまう恐怖（ダウンタイム）、思わぬ置き間違いの恐怖（設定ミス）、構築が遅くて壊れやすい恐怖、そして作り方を知る職人がいなくなる恐怖（属人化）の四つがありました。一人の頭の中にしか手順がなく、再現も共有も難しかったのです。
📝 採点ポイントを見る
□ ダウンタイム（停止）の恐怖に触れている
□ 設定ミスや遅さ・壊れやすさに触れている
□ 属人化（担当者が離れると作り方が失われる）に触れている
第3問この本の立ち位置

この本は「網羅的なリファレンス辞書」ではないと書かれています。では何に焦点を当てているのか説明してください。

✅ 解答例を見る
この本は、すべてのコマンドやリソースを引ける辞書ではなく、入門の一歩先の「現実世界で Terraform を使う方法」に焦点を当てています。なぜ使うのか、ワークフローにどう収まるか、どんなパターンやベストプラクティスがうまくいくか、といった公式ドキュメントに載っていない実践的な知識を扱います。細かい全機能の確認は公式ドキュメントの役割です。
📝 採点ポイントを見る
□ 網羅辞書ではなく実践ガイドだと述べている
□ パターン・ベストプラクティス・ワークフローなど実践面に触れている
□ 細かい全機能は公式ドキュメントの担当だと述べている
第4問サンプルコードの学び方

本書のサンプルコードを最も効果的に学ぶには、どんな進め方がよいと書かれていますか。

✅ 解答例を見る
サンプルコードはほとんどが「章の最後の完成形」なので、まず自分で最初からコードを書いてみて、最後の最後に GitHub の公式コードで答え合わせをするのが最も効果的です。2章から書き始め、各章の指示どおりに発展させていき、確認したいときや行き詰まったときだけサンプルを参照します。
📝 採点ポイントを見る
□ サンプルは「章の最後の完成形」だと理解している
□ 自分で書いてから答え合わせする流れを述べている
□ 行き詰まったときだけ参照する、という使い方に触れている
第5問第3版の主な進化

第3版では第2版から何が大きく変わったか、代表的な点を2つ以上挙げてください。

✅ 解答例を見る
第3版では、複数のプロバイダ（複数リージョン・アカウント・クラウド）を扱う7章と、シークレット（鍵・合言葉）を扱う6章が新しく加わりました。また、Terraform が 1.0 に達して後方互換が約束され安定性が増したこと、moved ブロックや precondition などの新機能、テストツールの比較追加など、数年分の進化を反映して100ページ以上加筆されています。
📝 採点ポイントを見る
□ 7章（複数プロバイダ）または6章（シークレット）の新設に触れている
□ 1.0 による後方互換・安定性向上に触れている
□ 新機能やページ増（100ページ以上加筆）など具体例に触れている
