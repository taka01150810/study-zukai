ファイルをアップロード2つの書き方

要するに：受け取り方は2通りあります。File() はまるごとメモリに読み込み、UploadFile は少しずつ読めます。

タカ
タカ師匠FastAPI は API の開発が主な対象で、本書のほとんどは JSON でのやり取りを使ってきた。けど次章で入力欄を扱うように、ファイルは「入力欄の一種のように」扱う。
タカ
タカ師匠FastAPI でのファイルの受け取りには2つの書き方がある。File() と UploadFile だ。

File()（小さいファイル）

タカ
タカ師匠File() を使う処理は、ふつうの形でも中断できる形でもよいけど、受け取っている間サーバに負担をかけない中断できる形のほうが優れている。
タカ
タカ師匠FastAPI はファイルを分割して受け取り、メモリ上で組み立て直す。だから File() は比較的小さなファイルにだけ使うべきだ。入力を JSON と考える代わりに、ファイルを入力欄の要素として送る形になる。

送られたファイルの大きさを返すだけの窓口です。

コードを見る（1行ずつ説明つき）
# 枠組み本体と、ファイルを受け取るための部品を取り込む。
from fastapi import FastAPI, File

# アプリ全体を作る。
app = FastAPI()

# /small への POST（データを送る動詞）を、この下の処理に結びつける。
@app.post("/small")
# async を付けて、受け取りの待ち時間に他の処理を進められるようにする。
# bytes は「数値の並びとしてのデータ」を表す種類。File() で受け取ると、この形になる。
async def upload_small_file(small_file: bytes = File()):
    # len は中身の長さ（ここではバイト数）を数える。それを文章にして返す。
    # この時点で、ファイルの中身はすべてメモリ上にある。
    return f"file size: {len(small_file)}"

HTTPie から送ります。記号の意味に注目してください。

コードを見る（1行ずつ説明つき）
# -f は「JSON ではなく、入力欄の形式で送る」という指定。ファイルを送るには必須。
# -b は本体だけを表示する指定。
# small_file は処理の引数名と一致させる。@ のあとが、送りたいファイル。
$ http -f -b POST http://localhost:8000/small small_file@1KB.bin
# --- 実行結果 ---
# "file size: 1000"
# 1000バイトのファイルを送ったので、その大きさが返ってきた。
タカ
タカ師匠確認のときの注意点。①-f が必要だ。JSON ではなく入力欄の形式で送るから。②small_file@1KB.bin の意味は、small_file が処理の引数名に対応し、@ がファイルを送る記号、1KB.bin が送るファイルだ。

Python からでも同じことができます。

コードを見る（1行ずつ説明つき）
# 問い合わせ用のパッケージを取り込む。
import requests

# 送り先の住所を用意する。
url = "http://localhost:8000/small"
# 送るファイルを組み合わせとして用意する。項目名は処理の引数名と合わせる。
# open の "rb" は「数値の並びとして読む」という指定。画像などはこの形で開く。
files = {'small_file': open('1KB.bin', 'rb')}
# files= に渡すと、入力欄の形式で送ってくれる。
resp = requests.post(url, files=files)
# 返ってきた内容を表示する。
print(resp.json())
# --- 実行結果 ---
# file size: 1000

UploadFile（大きいファイル）

タカ
タカ師匠大きなファイルには UploadFile を使う。これは、小さいうちはメモリ上に、大きくなったら自動でディスク上に置き換わる一時的な入れ物を包んだものだ。Python のファイルと同じように扱えるもので、読む・書く・位置を移動する、といった操作ができる。
タカ
タカ師匠受け取っている間にサーバが止まってしまわないよう、中断できる形の処理を使う。

大きさとファイル名の両方を返す窓口です。

コードを見る（1行ずつ説明つき）
# 枠組み本体と、大きなファイルを受け取るための型を取り込む。
from fastapi import FastAPI, UploadFile

# アプリ全体を作る。
app = FastAPI()

# /big への POST を結びつける。
@app.post("/big")
# UploadFile はそのまま種類の指定として書く。かっこは付けない。
async def upload_big_file(big_file: UploadFile):
    # read() で中身を読む。await を付けるのは、読み終わるまで待つが、
    # その間に他の問い合わせを処理してよい、という意味。
    # filename には、送り手側でのファイル名が入っている。
    return f"file size: {len(await big_file.read())}, name: {big_file.filename}"
タカ
タカ師匠注意。File() は数値の並びを作るのでかっこが必要だ。UploadFile は別の型そのものなので、種類の指定として直接書く。
コードを見る（1行ずつ説明つき）
# 1ギガバイトのファイルを送ってみる。書き方は小さいファイルのときと同じ。
$ http -f -b POST http://localhost:8000/big big_file@1GB.bin
# --- 実行結果 ---
# "file size: 1000000000, name: 1GB.bin"
# 大きさに加えて、送り手側でのファイル名も取れている。
コードを見る（1行ずつ説明つき）
# 問い合わせ用のパッケージを取り込む。
import requests

# 送り先の住所を用意する。
url = "http://localhost:8000/big"
# 大きなファイルを開いて、送る組み合わせに入れる。
files = {'big_file': open('1GB.bin', 'rb')}
# 送信する。大きいので時間がかかる。
resp = requests.post(url, files=files)
print(resp.json())
# --- 実行結果 ---
# file size: 1000000000, name: 1GB.bin

2つの書き方の比較

File()UploadFile
受け取る形数値の並び（bytes）ファイルと同じように扱えるもの
メモリの使い方全部をメモリ上に置く大きければディスクに逃がす
できる操作大きさを見る、中身を使う読む・書く・位置の移動、分割して読む
ファイル名取れないfilename で取れる
向く大きさ数メガバイトまで数百メガバイト〜
書き方x: bytes = File()x: UploadFile

🔎 具体例：大きなファイルを File() で受けるとどうなるか

1ギガバイトの動画を File() で受け取ると、その1ギガバイト分がすべてメモリ上に置かれます。サーバのメモリが4ギガバイトで、同時に5人がアップロードすると、5ギガバイトが必要になり、サーバが動かなくなります。

UploadFile なら、一定の大きさを超えた時点で自動的にディスク上の一時的な場所に移されます。メモリの使用量は一定に保たれ、同時に何人が送っても持ちこたえられます。

✅ この項のまとめ

  • File() = 小さいファイル向け。全部をメモリ上に置く
  • UploadFile = 大きいファイル向け。ファイルと同じように扱える
  • 読む・書く・位置の移動ができる
  • どちらも中断できる形の処理が推奨

タカ師匠送り出しも、受け取りと対応する書き方を使う。

FileResponse（小さいファイル）

タカ
タカ師匠まずは一度にまとめて送る版、FileResponse だ。

住所で指定された名前のファイルを、そのまま返す窓口です。

StreamingResponse（大きいファイル）

タカ
タカ師匠大きなファイル用は StreamingResponse だ。手が空いているときに他を止めないよう、中断できる形の処理を使う。誤りの確認は省いているけど、ファイルが無ければ開くところで失敗が出る。

ファイルを1メガバイトずつに分けて送る窓口です。

コードを見る（1行ずつ説明つき）
# 枠組み本体を取り込む。
from fastapi import FastAPI
# 少しずつ返すための部品を取り込む。
from fastapi.responses import StreamingResponse

# アプリ全体を作る。
app = FastAPI()

# 1回に読む大きさを決める。1024×1024 で、およそ1メガバイト。
CHUNK_SIZE = 1024 * 1024

# 住所の最後の部分を name として受け取る。
@app.get("/big/{name}")
async def download_big(name: str):
    # ファイルを少しずつ渡す処理を、この中で定義する。
    def gen_file():
        # ファイルを開く。with を使うと、抜けるときに自動で閉じられる。
        with open(name, mode="rb") as file:
            # := は「読んだ結果を chunk に入れ、同時にそれを条件としても使う」書き方。
            # 読むものが無くなると空になり、そこで繰り返しが終わる。
            while chunk := file.read(CHUNK_SIZE):
                # yield は「1つ渡して、ここで止まる」という指示。
                # 次に求められたときに、この続きから動く。
                yield chunk
    # 上で定義した処理を呼び、1つずつ渡してくれるものを受け取る。
    # この時点では、まだ1バイトも読まれていない。
    gen_expr = gen_file()
    # それを渡すと、FastAPI が求めるたびに1かたまりずつ送ってくれる。
    # media_type は「種類を特定しない、ただのデータ」という指定。
    return StreamingResponse(content=gen_expr, media_type="application/octet-stream")
タカ
タカ師匠gen_expr は、1つずつ渡してくれるもので、gen_file() が返したものだ。StreamingResponse は繰り返し取り出せるものを受け取るので、ファイルを分割して送れる。
コードを見る（1行ずつ説明つき）
# 大きなファイルを取りに行き、届いたバイト数を数える。
$ http -b http://localhost:8000/big/1GB.bin | wc -c
# --- 実行結果 ---
#  1000000000
#   10億バイト、つまり1ギガバイトが届いている。
#   サーバ側のメモリの使用量は、1回分の1メガバイト程度で済んでいる。
タカ
タカ師匠1ギガバイトのファイルが必要で、少し時間がかかる。

① 1かたまり読む

ファイルから1メガバイト分だけを読む。

メモリは1メガ分だけ
→

② 渡して止まる

読んだ分を渡し、その場で止まる。

続きの位置を覚えている
→

③ 送られる

受け取った側に送信される。

また①へ戻る
↺ ①〜③を1000回繰り返して、1ギガバイトを送りきります。どの瞬間もメモリ上にあるのは1メガバイト分だけです。

🔎 具体例：まとめて読むとどうなるか

1ギガバイトのファイルを file.read() で一度に読むと、その1ギガバイトがメモリに載ります。同時に3人がダウンロードすれば3ギガバイトです。

1メガバイトずつ読んで渡す形なら、3人同時でもメモリ上にあるのは3メガバイト分だけです。さらに、受け取る側は最初の1メガバイトが届いた時点で処理を始められるので、待ち時間も短くなります。

✅ この項のまとめ

  • FileResponse: まとめて送る。小〜中くらいのファイル向け
  • StreamingResponse: 分割して送る。大きなファイル向け
  • 1つずつ渡す処理で、分割して読む

静的ファイルを提供するフォルダごと配信する

要するに：app.mount("/path", StaticFiles(directory="...", html=True)) で、フォルダの中身をそのまま配信できます。

タカ
タカ師匠昔からの Web サーバは、サーバ上のファイルを、そのままの置き場所の形で扱える。FastAPI では StaticFiles でこれを実現する。

準備の手順

1

フォルダを作る

main.py と同じ場所に static/ というフォルダを作る（名前は自由）。

2

確認用のファイルを置く

static/abc.txt に abc :) と書いておく。

フォルダを住所に割り当てる設定です。

コードを見る（1行ずつ説明つき）
# 環境の情報を扱う機能を取り込む。
import os
# ファイルの場所を組み立てる機能を取り込む。
from pathlib import Path
# 枠組み本体を取り込む。
from fastapi import FastAPI
# フォルダをそのまま配信するための部品を取り込む。
from fastapi.staticfiles import StaticFiles

# アプリ全体を作る。
app = FastAPI()

# __file__ はこのファイル自身の場所。resolve() で完全な形にし、
# parents[0] でその1つ上、つまりこのファイルが入っているフォルダを得る。
# こう書くことで、どこから起動しても正しい場所を指せる。
top = Path(__file__).resolve().parents[0]
# /static という住所に、static フォルダの中身をまるごと割り当てる。
# html=True は、後で説明する index.html の自動応答を有効にする指定。
# name= は、この割り当てに付ける呼び名。コードの中から参照するときに使う。
app.mount("/static",
    StaticFiles(directory=f"{top}/static", html=True),
    name="static")
タカ
タカ師匠場所の計算は、static が main.py と同じところにあることを保証するためだ。__file__ は、このファイル（main.py）の完全な場所を表す。
コードを見る（1行ずつ説明つき）
# 置いたファイルを取りに行く。窓口を1つも書いていないのに取得できる。
$ http -b localhost:8000/static/abc.txt
# --- 実行結果 ---
# abc :)
# ファイルの中身がそのまま返ってきた。
タカ
タカ師匠html=True の意味はこうだ。そのフォルダに index.html がある場合、住所で明示しなくても自動で返してくれる。これは昔からの Web サーバに近い動きだ。
タカ
タカ師匠static/index.html に Oh. Hi! という内容を作って試してみよう。
コードを見る（1行ずつ説明つき）
# ファイル名を書かず、フォルダの住所だけで取りに行く。
$ http -b localhost:8000/static/
# --- 実行結果 ---
# Oh. Hi!
# index.html の中身が自動で返ってきた。html=True を外すと、これは返らない。
タカ
タカ師匠練習だ。static/ の下に xyz/ というフォルダを作り、2つのファイルを置く。①xyz.txt に xyz :(、②index.html に How did you find me?。ここでは答えを書かないので、自分で試してみて。

🔎 具体例：この練習で確かめられること

/static/xyz/xyz.txt にアクセスすると xyz :( が返ります。下の階層のフォルダも、自動的に扱われることが分かります。

/static/xyz/ にアクセスすると How did you find me? が返ります。index.html の自動応答は、一番上のフォルダだけでなく、下の階層のフォルダでも同じように働くことが確かめられます。

✅ この項のまとめ

  • StaticFiles でフォルダごと配信
  • app.mount() で住所に割り当てる
  • html=True で index.html を自動で返す
  • 下の階層のフォルダにも自動で対応する

章末の理解度チェック全5問

第1問File() と UploadFile

FastAPI の File() と UploadFile、どう使い分けますか？ それぞれの特徴と、向いている用途を説明してください。

✅ 解答例
File() はファイル全体を数値の並びとしてメモリに広げる。小さなファイル（数メガバイトまで）向け。単純だが、巨大なファイルを渡すとメモリが足りなくなる。UploadFile は Python のファイルと同じように扱えるものを包んでいて、読む・書く・位置の移動などで分割して読める。大きなファイル（数百メガバイト〜）向け。ファイル名や種類も取れる。中断できる形の処理と組み合わせると、待ち時間に他の処理を進められる。
📝 採点ポイント
□ File() がメモリに全部広げる、UploadFile がファイルと同じように扱える、と述べている
□ 大きさによる使い分けに触れている
□ 中断できる形の処理との組み合わせに触れている
第2問FileResponse と StreamingResponse

送り出し用の FileResponse と StreamingResponse の違いは何ですか？ 大きなファイルを送る場合の書き方を示してください。

✅ 解答例
FileResponse はファイルをまとめて読み込んで送る。小〜中くらいのファイル向け。StreamingResponse は分割して送れる。大きなファイル向け。書き方は、1つずつ渡す処理を作って yield でかたまりを返し、それを StreamingResponse(content=...) に渡す。media_type には「種類を特定しないデータ」を表す指定を使う。
📝 採点ポイント
□ 前者がまとめて、後者が分割して、と述べている
□ 1つずつ渡す処理と yield の形を示している
□ media_type の指定に触れている
第3問StaticFiles の使い方

FastAPI で static/ フォルダの中身を /static/ という住所で公開するコードを書いてください。html=True の役割も説明してください。

✅ 解答例
from fastapi.staticfiles import StaticFiles と書き、app.mount("/static", StaticFiles(directory="static", html=True), name="static") と書く。html=True を指定すると、そのフォルダ（または下の階層のフォルダ）に index.html がある場合、住所で明示しなくても自動で返してくれる。たとえば /static/ にアクセスすると /static/index.html の内容が返る。昔からの Web サーバの動きに近づける指定。
📝 採点ポイント
□ app.mount() を使ったコードを書いている
□ StaticFiles(directory=..., html=True) の指定を正しく書いている
□ html=True の役割（index.html の自動応答）を説明している
第4問ファイル処理に必要なパッケージ

FastAPI でファイルの受け取りと送り出しを実装するために必要な、追加のパッケージを2つ挙げて、それぞれの役割を説明してください。

✅ 解答例
①python-multipart：1回の送信の中にファイルと文字を混ぜた形式を読み解くためのパッケージ。ファイルを受け取るときに FastAPI が内部で使う。pip install python-multipart。②aiofiles：ファイルの読み書きを、待ち時間に他の処理を進められる形で行うためのパッケージ。大きなファイルを中断できる形の処理で扱う際に必要。pip install aiofiles。
📝 採点ポイント
□ python-multipart と aiofiles の2つを挙げている
□ それぞれの役割を説明している
□ 導入のコマンドに触れている
第5問HTTPie でのファイル送信

HTTPie で FastAPI のファイル受け取りの窓口（引数名 small_file）に data.bin を送るコマンドを書いてください。各指定の意味も説明してください。

✅ 解答例
http -f -b POST http://localhost:8000/small small_file@data.bin と書く。-f：入力欄の形式で送る指定。FastAPI 側の File() や UploadFile で受けるには必須。-b：返事の本体だけを表示する（付随情報を省く）。POST：使う動詞。small_file@data.bin：small_file が処理の引数名、@data.bin は「ファイル data.bin を、small_file という項目として送る」という意味。
📝 採点ポイント
□ -f の意味（入力欄の形式で送る）を説明している
□ small_file@data.bin の書き方を正しく解釈している
□ -b（本体だけ）に触れている
