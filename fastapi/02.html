パッケージ package

他の人が作って公開している、そのまま使える機能のかたまり。取り込めば自分で書かずに済みます。

pip

公開されているパッケージを取ってきて、自分のパソコンに入れるためのコマンド。pip install 名前 で使います。

仮想環境 venv

プロジェクトごとに用意する、パッケージの専用インストール先フォルダ。そこを使うと決めておくと、他のプロジェクトに影響を与えずに済みます。

有効化 activate

「これから python や pip を打ったら、この仮想環境のものを使う」と切り替える操作のことです。

Poetry ポエトリー

パッケージの取得と仮想環境の管理をまとめて行う道具。設定ファイルに書いた通りの組み合わせを再現できます。

依存関係 dependency

あるパッケージが動くために必要な、別のパッケージのつながり。A が B を必要とし、B が C を必要とする、という連鎖になります。

ピン留め pinning

使うバージョンを1つに固定すること。「2.1.3 だけを使う」と決めれば、環境が変わっても同じものが入ります。

Black

Python のコードの見た目（空白や改行の入れ方）を、決まった形に自動でそろえる道具です。

pytest

「このコードは期待通りに動くか」を自動で確かめるプログラムを書くための道具。実務で最も広く使われています。

Git

コードの変更履歴を記録し、いつでも過去に戻せるようにする道具。複数人での共同作業にも使います。

リポジトリ repository

コードとその変更履歴をまとめて置いておく保管場所のことです。

pre-commit

変更を記録する直前に、決めておいた確認（整形やテスト）を自動で走らせる仕組み。通らなければ記録できません。

CI 継続的インテグレーション

変更を共有の保管場所に送るたび、サーバー側で自動的にテストを実行する仕組みです。

オブジェクト object

Python がデータを持つときの入れ物。整数の 5 も、関数も、自分で作った型のデータも、すべてこの形で扱われます。

強く型付けされている

データの種類（整数、文字列など）が勝手に別の種類に変わらない、ということ。数字と文字を混ぜて計算しようとするとエラーになります。

mutable／immutable

mutable は中身を後から変えられるデータ（リストなど）。immutable は一度作ったら変えられないデータ（文字列やタプルなど）です。

参照カウント

そのデータが今いくつの名前から使われているかを数えた数。0 になると、そのデータは自動的に片づけられます。

スコープ scope

ある名前が通用する範囲。関数の中で作った名前は、その関数の外からは見えません。

型ヒント type hint

「この値は整数」「ここは文字列を返す」とコードに書き添える表記。実行時に強制はされず、道具と読み手のための情報です。

mypy

型ヒントの書き方と実際の使い方が食い違っていないかを、実行前に調べてくれる道具です。

Pydantic

型ヒントを使ってデータの形を宣言し、受け取った値がその形に合っているかを実行時に確かめてくれるパッケージです。

WSGI

Python のプログラムと Web サーバーをつなぐ、順番に1つずつ処理する方式の取り決めです。

ASGI

WSGI の非同期版。返事待ちの間に別の処理を進められる方式の取り決めです。

Starlette

ASGI に対応した軽量な土台。FastAPI はこの上に作られています。

Uvicorn

ASGI 方式で動く Web サーバー。FastAPI で作ったプログラムを実際に動かすときに使います。

モジュール／パッケージ（Python）

コードを機能ごとにファイル単位・フォルダ単位に分けたもの。取り込んで使います。

仮想環境を作るコマンドです。実行すると、今いる場所に venv1 という名前のフォルダができます。

コードを見る（1行ずつ説明つき）
# python に -m を付けると、指定した機能を呼び出せる。ここでは venv を呼ぶ。
# 最後の venv1 が、これから作るフォルダの名前。好きな名前でよい。
$ python -m venv venv1
# --- 実行結果 ---
# 画面には何も出ない。かわりに venv1 というフォルダができている。
# その中に、このプロジェクト専用の python と pip が入っている。

コードを見る（1行ずつ説明つき）

# venv1/bin/activate には「これからは venv1 の中を優先して使う」という設定が書かれている。
$ source venv1/bin/activate
# --- 実行結果 ---
# (venv1) $     ← 入力待ちの行の先頭に環境名が付き、切り替わったことが分かる。
# この状態で pip install をすると、すべて venv1 の中に入る。
タカ
タカ師匠これで pip install ... をやると、すべて venv1 の下に入る。Python のプログラムも、その中の Python とモジュールを優先して使うようになる。

変数は名前付けであるPython 独特の考え方

要するに：Python の変数は「名前」であり、メモリ上の場所そのものではありません。値を代入することは「その名前を、あるデータに結びつけ直す」操作です。

ハル
ハルPython の変数って、他の言語と違うって聞いたんですけど…。
タカ
タカ師匠ここ重要。じっくり行こう。まず Python におけるオブジェクトという言葉から。

オブジェクトとは

タカ
タカ師匠ソフトウェアの世界で「オブジェクト」にはたくさんの定義があるけど、Python ではこう。整数の 5 から関数、自分で定義した型のデータまで、プログラム内のあらゆるデータを包む入れ物のことだ。
タカ
タカ師匠オブジェクトは内部に次の情報を持つ。①区別のためのID、②機械に対応する低いレベルの型、③具体的な値、④参照カウント（いくつの名前がそれを使っているか）。
ハル
ハル「強く型付けされている」って何ですか？
タカ
タカ師匠Python はオブジェクトのレベルで強く型付けされている。つまり、ある値が整数なら整数、文字列なら文字列。途中で型が勝手に変わったりしない（C 言語のような自動的な変換は基本ない）。
タカ
タカ師匠オブジェクトは、値が変えられるかどうかで2種類。mutable（変更可能）と immutable（変更不可）。たとえば list は mutable、tuple や str は immutable だ。
🆔

ID

そのデータを他と区別するための番号。

🔢

型

整数なのか、文字列なのか、といった種類。

📦

値

実際の中身そのもの。

🔗

参照カウント

いくつの名前がそのデータを使っているかの個数。0 になると片づけられます。

✏️

mutable（変更可能）

作ったあとで中身を変えられます。例：list（一覧）。要素を後から足したり消したりできます。

🔒

immutable（変更不可）

作ったら中身を変えられません。例：tuple、str（文字列）。変えたいときは新しく作り直します。

他の言語との大きな違い

タカ
タカ師匠ここからが他の言語との大きな違いだ。多くの言語では、変数 = メモリ上の場所を指していて、新しい値を代入するとそのメモリの中身が書き換わる。
ハル
ハルそれが普通だと思ってました。
タカ
タカ師匠C 言語が高速な理由の一つでもある。翻訳する側が「どの変数がどこにあるか」を全部把握しているから速い。代わりに、開発者は「各変数に正しい型の値しか入れない」よう注意する必要がある。
タカ
タカ師匠ところが Python はそうじゃない。Python の変数は「名前」に過ぎない。メモリ上にあるデータ本体に、一時的に結びつけられた呼び名なんだ。
タカ
タカ師匠変更できないデータを指している名前に新しい値を代入する場合、実際には「新しいデータを作って、その名前をそちらに結び直す」操作になる。
タカ
タカ師匠そのとき、元のデータは（他の名前から使われていなければ）参照カウントが 0 になって、メモリから片づけられる。
ハル
ハルわ、メモリの管理が見えないところで動いてるんですね。
タカ
タカ師匠そう。a = 5 は「5 というデータを用意して、a という名前をそこに結びつける」。a = 10 は「10 という新しいデータを作って、a の結びつけ先をそちらに変える。もう誰も 5 を使っていなければ、5 は片づけられる」ということだ。

名前がどのデータに結びついているかを、番号で確かめる例です。id() はそのデータの区別用の番号を返す命令です。

コードを見る（1行ずつ説明つき）
# a という名前を、5 というデータに結びつける。
a = 5
# id は「そのデータの区別用の番号」を返す。番号は実行のたびに変わる。
print(id(a))
# --- 実行結果（番号は環境により異なる） ---
# 4304123456

# a に 10 を代入する。5 の中身が書き換わるのではなく、
# 10 という別のデータが用意され、a の結びつけ先がそちらに変わる。
a = 10
# もう一度番号を見ると、さっきと違う番号になっている。別のデータを指している証拠。
print(id(a))
# --- 実行結果 ---
# 4304123616

🔎 具体例：リストが「連動して」変わる場面

a = [1, 2, 3] と書き、続けて b = a と書いたとします。ここで b.append(4) を実行すると、a を表示しても [1, 2, 3, 4] になります。b = a は中身をコピーしたのではなく、同じデータに 2 つ目の名前を付けただけだからです。

一方 a = 5 のあとに b = a、続けて b = 6 とした場合、a は 5 のままです。数値は変更できないデータなので、b = 6 は「b の結びつけ先を、新しく作った 6 に変える」操作になり、a には影響しません。この違いが、mutable と immutable の区別が実際に効いてくる場面です。

スコープと命名

タカ
タカ師匠変数のスコープとは、ある名前が同じデータを指しているコードの範囲（関数の中など）のこと。違う範囲で同じ名前を使っても、別のデータを指すことになる。
タカ
タカ師匠Python では同じ名前が途中で違うデータを指すこともできるけど、それは必ずしも良いやり方じゃない。100行目の x と20行目の x が同じ範囲の同じものを指しているか、コードを追って判断するのは骨が折れる。
タカ
タカ師匠ちなみに x という名前自体ひどい命名だ。x に意味を与えるような名前を選ぶべきだ。

💡 なぜこれが必要か／これを知ったらできること

  • 「a = b でリストが連動して変わる」という現象を、名前と実体の関係で説明できる
  • mutable と immutable の違いに敏感になり、関数に値を渡すときの落とし穴を避けられる

第1問仮想環境

「仮想環境」とは何か、なぜ必要なのか、自分の言葉で説明してください。

✅ 解答例
仮想環境はプロジェクトごとに用意する、パッケージの専用インストール先フォルダ。pip で入れるライブラリを、システム全体ではなくこのフォルダの中だけに入れることで、別のプロジェクトと干渉しないようにできる。たとえば「A プロジェクトでは pandas 1.5、B プロジェクトでは pandas 2.0」を共存させたいときに必要。
📝 採点ポイント
□ プロジェクト単位で分ける、という考え方に触れている
□ システム全体に影響を与えないための仕組みだと言及している
□ 異なるバージョンの共存例など、具体的な利点を挙げている
第2問変数とオブジェクト

Python の「変数」と他言語（C言語など）の「変数」はどう違いますか？「名前」「オブジェクト」というキーワードを使って説明してください。

✅ 解答例
C 言語などでは変数はメモリ上の場所そのもの。新しい値を代入するとメモリの中身が上書きされる。一方 Python の変数は「名前」に過ぎず、メモリ上のオブジェクト（実際のデータ）に結びつけられた呼び名。a = 10 は「10 という新しいオブジェクトを作り、a という名前をそれに結び直す」操作。古いオブジェクトは誰も使わなくなれば自動で片づけられる。
📝 採点ポイント
□ C 言語などとの違い（メモリの直接書き換え vs 名前の結び直し）に触れている
□ 「変数 = 名前」「オブジェクトに名前を結びつける」という関係を説明している
□ 使われなくなったオブジェクトが片づけられる、というメモリ管理に言及している
第3問型ヒントの役割

Python の型ヒントは何のためにあるのですか？「実行時には強制されない」のに、どんな価値があるのですか？ FastAPI における特殊な使い方も含めて説明してください。

✅ 解答例
型ヒントは変数・引数・戻り値の型を明示する書き添えで、実行時には確認されない。価値は「人間が読みやすい」「mypy などの型を調べる道具や編集画面の補完が活用できる」「説明書の代わりになる」など。FastAPI はこれをただのメモではなく、Pydantic を通じて「受け取ったデータを実行時に検証する」ための情報源として活用する。これが FastAPI の強力さの源になっている。
📝 採点ポイント
□ 「実行時には強制されない」点に触れている
□ 人間や型チェックの道具（mypy）にとっての価値を挙げている
□ FastAPI が Pydantic を通じて型ヒントを実行時の検証に応用している点を説明している
第4問WSGI と ASGI

WSGI と ASGI の違いを自分の言葉で説明してください。なぜ ASGI が新しく登場したのですか？

✅ 解答例
WSGI はアプリケーションと Web サーバをつなぐ古い同期の Python 標準。ASGI はその非同期版で、新しく登場した標準。同期だと返事待ちの間に処理装置が何もできず遅くなるため、現代の数百万同時接続を支えるには非同期処理が必要になり、ASGI が作られた。FastAPI は ASGI 側のフレームワーク。
📝 採点ポイント
□ WSGI = 同期、ASGI = 非同期、という対比に触れている
□ 非同期が必要な理由（多くの接続、返事待ち）に言及している
□ FastAPI が ASGI 側であることに触れている
第5問FastAPI の出自

📝 採点ポイント
□ 作者と公開年に触れている
□ 土台の2パッケージ（Starlette、Pydantic）を挙げている
□ Python の Web フレームワークとしての位置（Django/Flask に並ぶ）に言及している

# 2つの整数を受け取り、足した結果（整数）を返す、という書き添え付きの処理。
def add(a: int, b: int) -> int:
    # 受け取った2つを足して、その結果を返す。
    return a + b

# わざと文字列を渡してみる。Python 自体はこれを止めない。
print(add(1, "2"))

# TypeError: unsupported operand type(s) for +: 'int' and 'str'

# --- mypy ファイル名.py を実行した結果 ---
