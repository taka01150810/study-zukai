ゲームロジックを分割する途中経過をどこに置くか

要するに：Web は前回を覚えていないので、途中経過の置き場所が課題になります。選択肢は3つあり、本書は3つめを採ります。

タカ

タカ

💻

① 画面側で完結

すべての状態をブラウザ側で持つ。
良い点：サーバへの負担が小さく、動きが速い。
困る点：JavaScript の知識が要る。複雑な判断を書きにくい。記録が残らない。

🗄️

② サーバ側で持つ

最初の呼び出しでゲームの番号を発行し、以降はその番号でサーバが状態を管理し、データベースに保存する。
良い点：確実に記録が残る。複雑な判断も書ける。
困る点：読み書きが増え、サーバの負担が大きい。

🔄

③ 両方で分担

画面側とサーバ側で役割を分ける。画面は裏で通信して、一部だけを書き換える。
良い点：釣り合いが良く、役割がはっきりする。
困る点：両方の知識が必要。

🔎 具体例：どう分担しているか

「隠された名前」はサーバが決めますが、それを画面側に渡してしまいます。「これまで何回推測したか」「どの行を表示しているか」は画面側だけが持ちます。サーバは、送られてきた推測と名前を比べて採点を返すだけで、前回のことは何も覚えていません。

Webパート1：ゲーム初期化住所の衝突を避ける

要するに：既存の住所と衝突しないよう、一番上の階層に /game を作ります。

タカ
タカ師匠新しい窓口が2つ欲しい。生き物の名前を使うので /creature/game かな…と思うけど、既存の /creature/{name} と重なるので、FastAPI がそちらを先に選んでしまう可能性がある。だから一番上の階層に /game を作る。

⚠️ なぜ衝突するのか

/creature/{name} は「/creature/ の後ろにある文字を、すべて名前として受け取る」という指定です。ここに /creature/game を追加すると、game という文字も「名前」として解釈されうる、という状態になります。どちらが選ばれるかは並び順に左右されるので、意図しない動きを避けるために、別の住所にします。

ゲームを始める窓口です。名前を取り出して、テンプレートに渡します。

コードを見る（1行ずつ説明つき）
# 窓口のまとめと、届いた問い合わせを表す型を取り込む。
from fastapi import APIRouter, Request
# テンプレートを扱う部品を取り込む。
from fastapi.templating import Jinja2Templates
# ゲームのためのサービス層を取り込む。
import service.game as service

# この中の住所は /game から始まる。一番上の階層に置くので、他と重ならない。
router = APIRouter(prefix="/game")
# テンプレートの置き場所を指定する。
templates = Jinja2Templates(directory="template")

# 末尾のスラッシュの有無、どちらでも受け付けるようにデコレータを2つ重ねる。
@router.get("")
@router.get("/")
# request を引数に書く。テンプレートに渡すために必要。
def game_start(request: Request):
    # でたらめに1つ、名前を取り出す。これが今回の答えになる。
    name = service.get_word()
    # テンプレートに、問い合わせそのものと、取り出した名前を渡す。
    # 組み立てられた HTML が、ブラウザに返る。
    return templates.TemplateResponse(
        "game.html",
        {"request": request, "name": name},
    )
タカ
タカ師匠FastAPI は、この処理が request を引数に持ち、それをテンプレートに渡すことを求める。

作ったまとまりを、アプリ本体に組み込みます。

コードを見る（1行ずつ説明つき）
# サーバを動かす道具と、枠組み本体を取り込む。

from fastapi import FastAPI
# 3つのまとまりを取り込む。game が新しく加わった。

# これまでのまとまりを組み込む。

app.include_router(creature.router)
# ゲームのまとまりを組み込む。これで /game が使えるようになる。

# 直接動かされたときだけサーバを起動する。
if __name__ == "__main__":
    uvicorn.run("main:app", reload=True)

Webパート2：ゲームのステップ1つのファイルに全部入り

要するに：1つのテンプレートに HTML・装飾・JavaScript をまとめます。裏の通信で推測を送り、結果を色で表示します。

画面の全体です。長いので、上から順に説明を追ってください。

コードを見る（1行ずつ説明つき）
<html>
<head>
<!-- ここから見た目の指定。 -->
<style>
/* 入力欄の見た目。幅を狭くし、文字を中央にそろえる。 */
.guess-input { width: 30px; margin: 2px; text-align: center; }
/* 位置も文字も合っている場合の背景色（緑）。 */
.H { background-color: lightgreen; }
/* 文字は含まれるが位置が違う場合の背景色（黄）。 */
.C { background-color: yellow; }
/* 含まれない場合の背景色（灰）。 */
.M { background-color: lightgray; }
</style>
</head>
<body>
<h1>Cryptidの名前を当てよう</h1>

<div id="game">
  <!-- Jinja の書き方で、名前の文字数を計算して表示している。 -->
  <p>文字数: <span id="name-length">{{ name | length }}</span></p>
  <!-- 入力欄を置く場所。中身は JavaScript で作る。 -->
  <div id="guess-area"></div>
  <!-- 送信のボタン。 -->
  <button id="submit-btn">送信</button>
  <!-- これまでの推測の結果を並べる表。行は後から追加される。 -->
  <table id="results"><tbody></tbody></table>
</div>

<script>
// サーバが選んだ名前が、ここに文字として埋め込まれる。
// 二重の波かっこは Jinja の差し込みで、ブラウザに届く時点では実際の名前になっている。
const SECRET_NAME = "{{ name }}";
// 名前の文字数を覚えておく。入力欄の数と、正解の判定に使う。
const nameLength = SECRET_NAME.length;

// 文字数と同じ数の入力欄を作る処理。
function createGuessInputs() {
  // 入力欄を置く場所を取得する。
  const area = document.getElementById("guess-area");
  // 中身を空にする。2回目以降の推測のために、毎回作り直す。
  area.innerHTML = "";
  // 文字数の分だけ繰り返す。
  for (let i = 0; i < nameLength; i++) {
    // 入力欄を1つ作る。
    const input = document.createElement("input");
    // 文字を入れる種類にする。
    input.type = "text";
    // 1文字だけ入るように制限する。
    input.maxLength = 1;
    // 見た目の指定を適用するための名前を付ける。
    input.className = "guess-input";
    // 作った入力欄を、画面に追加する。
    area.appendChild(input);
  }
}

// 推測を送信する処理。async を付けると、通信の返事を待てる。
async function submitGuess() {
  // 画面上の入力欄をすべて取得する。
  const inputs = document.querySelectorAll(".guess-input");
  // 各入力欄の値を取り出し、つなげて1つの文字列にする。
  const guess = Array.from(inputs).map(i => i.value).join("");
  // 文字数が足りていなければ、知らせて中断する。
  if (guess.length !== nameLength) {
    alert("文字数が違います");
    return;
  }
  // サーバに送る。await を付けているので、返事が来るまでここで待つ。
  // 画面全体は切り替わらず、この通信だけが裏で行われる。
  const resp = await fetch("/game", {
    // データを送るので、動詞は POST。
    method: "POST",
    // 中身が JSON であることを伝える。
    headers: {"Content-Type": "application/json"},
    // 推測と、隠された名前の両方を送る。サーバは覚えていないので、毎回両方を送る。
    body: JSON.stringify({guess: guess, name: SECRET_NAME}),
  });
  // 返ってきた内容を、扱える形に直す。
  const data = await resp.json();
  // 採点の結果の文字列を取り出す。HHCM のような形になっている。
  const score = data.score;
  // 結果を並べる表の、中身の部分を取得する。
  const tbody = document.querySelector("#results tbody");
  // 新しい行を1つ作る。
  const tr = document.createElement("tr");
  // 推測の文字数の分だけ繰り返す。
  for (let i = 0; i < guess.length; i++) {
    // マスを1つ作る。
    const td = document.createElement("td");
    // そのマスに、推測した文字を入れる。
    td.textContent = guess[i];
    // 採点の記号を、そのまま見た目の指定の名前として使う。
    // H なら緑、C なら黄、M なら灰になる。
    td.className = score[i];
    // 行にマスを追加する。
    tr.appendChild(td);
  }
  // 完成した行を、表に追加する。これで1回分の結果が画面に残る。
  tbody.appendChild(tr);
  // 全部が H なら、正解。repeat は同じ文字を指定回数つなげる命令。
  if (score === "H".repeat(nameLength)) {
    alert("正解！おめでとう！");
  } else {
    // まだなら、入力欄を作り直して次の推測に備える。
    createGuessInputs();
  }
}

// 送信ボタンが押されたら、上の処理を呼ぶように設定する。
document.getElementById("submit-btn").addEventListener("click", submitGuess);
// 画面が表示されたとき、最初の入力欄を作っておく。
createGuessInputs();
</script>
</body>
</html>

🔎 具体例：採点の記号がそのまま色になる仕組み

サーバは "HCMH" のような文字列を返します。画面側は、1文字目の H をそのままマスの見た目の名前として設定します。

見た目の指定に .H { background-color: lightgreen; } と書いてあるので、そのマスが緑になります。つまり、採点の記号と見た目の名前をそろえておくことで、変換の処理を1行も書かずに色が付きます。

サービスパート2：採点1文字ずつ比べる

要するに：採点は1文字ずつの記号の並びです。大文字と小文字は区別せず、長さが違えば空の文字列を返します。

送られてくるデータの形と、採点の処理です。

コードを見る（1行ずつ説明つき）
# データの形を定義するための元を取り込む。
from pydantic import BaseModel

# 送られてくる内容の形を決める。2つの項目を持つ。
class Guess(BaseModel):
    # 隠された名前。サーバは覚えていないので、毎回送ってもらう。
    name: str
    # 利用者が入力した推測。
    guess: str

# 採点する処理。結果は H/C/M を並べた文字列。
def score(item: Guess) -> str:
    # 比べる前に、両方を小文字にそろえる。大文字で入力されても同じ扱いになる。
    name = item.name.lower()
    guess = item.guess.lower()
    # 長さが違う場合は採点できないので、空の文字列を返す。
    if len(guess) != len(name):
        return ""
    # 1文字ずつの結果を、ここにためていく。
    result = []
    # 推測を1文字ずつ、その位置の番号と一緒に取り出す。
    for i, ch in enumerate(guess):
        # 同じ位置の文字と一致するかを確かめる。
        if i < len(name) and ch == name[i]:
            # 位置も文字も合っている。
            result.append("H")
        # 位置は違うが、名前のどこかに含まれているかを確かめる。
        elif ch in name:
            # 文字は含まれるが、位置が違う。
            result.append("C")
        else:
            # その文字は含まれない。
            result.append("M")
    # ためた結果を、1つの文字列につなげて返す。
    return "".join(result)
# --- 動きの例 ---
# name="yeti", guess="yeti" → "HHHH"
# name="yeti", guess="eyit" → "CCCC"（全部含まれるが、全部位置が違う）
# name="yeti", guess="abcd" → "MMMM"
タカ
タカ師匠採点は1文字ずつの文字列だ。H は位置も文字も合っている、C は文字は含まれるが位置が違う、M は含まれない。大文字と小文字は、両方を小文字にそろえてから比べる。長さが違えば空の文字列を返す。

採点の窓口を追加します。

コードを見る（1行ずつ説明つき）
# データの形と、採点の処理を取り込む。
from service.game import Guess, score

# 末尾のスラッシュの有無、どちらでも受け付ける。
@router.post("")
@router.post("/")
# 送られた内容が Guess の形として受け取られる。合わなければ自動で 422 が返る。
def game_step(guess: Guess) -> dict:
    # 採点した結果を、項目名を付けて返す。画面側はこの score を読む。
    return {"score": score(guess)}

🟩

同じ位置に、同じ文字がある。

🟨

C

⬜

M

名前のどこにも含まれない。

✅ この項のまとめ

  • 採点の結果: H/C/M を並べた文字列
  • 大文字と小文字は区別しない
  • 長さが違えば空の文字列

テストだ！いくつもの入力をまとめて確かめる

要するに：入力と期待する結果を一覧に並べ、1つの処理でまとめて確かめます。

5つの場合を、1つのテストで確かめます。

コードを見る（1行ずつ説明つき）
# 確認の道具を取り込む。
import pytest
# データの形と、採点の処理を取り込む。
from service.game import Guess, score

# 1つめの指定は、受け取る引数の名前をカンマで並べたもの。
# 2つめは、確かめたい場合を並べた一覧。この5組が順に試される。
@pytest.mark.parametrize("name,guess,expected", [
    # 完全に一致する場合。すべて H になるはず。
    ("yeti", "yeti", "HHHH"),
    # 大文字が混ざっている場合。区別しないので、同じ結果になるはず。
    ("yeti", "Yeti", "HHHH"),
    # 文字はすべて含まれるが、位置が全部違う場合。すべて C になるはず。
    ("yeti", "eyit", "CCCC"),
    # どの文字も含まれない場合。すべて M になるはず。
    ("yeti", "abcd", "MMMM"),
    # 長さが違う場合。空の文字列が返るはず。
    ("yeti", "yetii", ""),
])
# 引数の名前を、上で並べた名前とそろえる。
def test_score(name, guess, expected):
    # 渡された値で、送られてくる内容の形を組み立てる。
    item = Guess(name=name, guess=guess)
    # 採点の結果が、期待どおりかを確かめる。この行が5回実行される。
    assert score(item) == expected
コードを見る（1行ずつ説明つき）

$ pytest -q test_game.py
# --- 実行結果 ---
# .....                                               [100%]
# 5 passed in 0.05s
# ドットが5つ。1つの処理を書いただけで、5件分の確認になっている。
タカ
タカ師匠この書き方で、5つの場合を一度に確かめられる。テストの中で繰り返しを書く必要がない。

🔎 具体例：この書き方の利点

もし「同じ文字が2回出てくる場合」も確かめたくなったら、一覧に1行足すだけです。処理の中身は変えません。

✅ この項のまとめ

  • いくつもの場合を、1つの処理でまとめて確かめる
  • 入力と期待する結果を一覧にする書き方
  • 繰り返しを自分で書くより読みやすい

# でたらめな選び方をするための標準の機能を取り込む。

# データベースへの取っ手を取り込む。
from data.init import curs

# でたらめに1つ、名前を返す処理。
def get_random_creature_name() -> str:
    # order by random() は、行をばらばらの順に並べる指定。
    # limit 1 は、その先頭の1件だけを取る指定。
    # この2つを組み合わせると、でたらめな1件が取れる。
    qry = "select name from creature order by random() limit 1"

    curs.execute(qry)

    # 取り出したのは名前だけなので、その0番目を返す。
    return row[0]

第1問途中経過の持ち方の選択肢

Web が前回を覚えていない場合、複数の段階にわたるゲームの「途中経過」をどこに持つかについて、3つの選択肢を挙げて、それぞれの良い点と困る点を説明してください。

✅ 解答例
①画面側で完結：すべての状態をブラウザ側で管理する。良い点はサーバへの負担が小さく、動きが速いこと。困る点は JavaScript の知識が必要で、複雑な判断を扱いにくく、記録が残しにくいこと。②サーバ側で持つ：最初の呼び出しでゲームの番号を発行し、以降その番号でサーバが状態を管理する。良い点は確実に記録が残り、複雑な判断も書けること。困る点は読み書きが増え、サーバの負担が大きいこと。③両方で分担：本書のゲームが採る形。良い点は釣り合いが良く、役割がはっきりすること。困る点は両方の知識が必要なこと。
📝 採点ポイント
□ 3つの選択肢を挙げている
□ それぞれの良い点・困る点に触れている
□ 本書がどれを採ったかを述べている

第5問住所の設計での衝突の回避

□ 重なりを避けるために一番上の階層を選んだ理由を説明している
