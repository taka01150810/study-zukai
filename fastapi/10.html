DB-API

Python からデータベースを扱うときの、共通の呼び出し方の取り決めです。

接続 connection

データベースとやり取りするための、つながりを表すもの。connect() で作ります。

カーソル cursor

問い合わせを実行し、その結果を1件ずつ取り出すための取っ手のようなものです。

SQL

データベースに「この条件のデータを取ってきて」「これを保存して」と伝えるための言語です。

SQLite

専用のサーバを持たず、1つのファイルにデータを保存する小さなデータベースです。

パラメータの結びつけ

SQL の中に値を直接書かず、別に渡すやり方。文字列を勝手に足されるのを防げます。

SQLインジェクション

入力欄に SQL の一部を書き込んで、想定外の操作をさせる攻撃です。

主キー primary key

その表の中で1件を特定するための項目。重複できません。

テーブルスキャン

表の全部の行を1行ずつ見ていくこと。件数が多いと遅くなります。

環境変数

プログラムの外側から渡す設定。コードを変えずに動きを変えられます。

Twelve-Factor App

Web アプリの作り方の指針をまとめたもの。設定をコードから分けることを勧めています。

シングルトン

何度取り込んでも、実際に動くのは1回だけ、という性質のことです。

末尾スラッシュ問題

/explorer と /explorer/ が別の住所として扱われるために起きる食い違いです。

405 Method Not Allowed

「その住所は存在するが、その動詞では受け付けていない」という返事の番号です。

422

送られた内容が、決めておいた形に合っていないときに返す番号です。

201 Created

新しく作られたことを表す番号。作成の窓口で返すのが一般的です。

204

成功したが返す中身は無い、という番号。削除の窓口でよく使われます。

HTTPException

FastAPI に「この番号のエラーで返して」と伝えるための知らせです。

IntegrityError

データベースの決まり（重複禁止など）に反したときに出る、SQLite からの知らせです。

rowcount

直前の操作で、実際に何行が影響を受けたかの数です。

:memory:

ファイルではなくメモリ上にデータベースを作る指定。終了すると消えます。

fixture

テストで使う準備済みのデータや状態を、必要なテストに渡す pytest の仕組みです。

スコープ fixtureの

その準備をいつ作り直すか。1件ごとか、全体で1回かを決めます。

pytest.raises

「この中で失敗が起きるはず」と書くための、テスト用の書き方です。

DB-API接続 → カーソル → 実行 → 取り出し

要するに：DB-API は「接続 → カーソル → 実行 → 取り出し」の流れです。値の渡し方は名前付き（:name）がおすすめです。

タカ
タカ師匠Python は20年以上前から、表形式のデータベースを扱うときの共通の呼び出し方として DB-API（PEP 249）を持っている。データベース用の Python の接続部品を書く人は、最低限これを用意することが期待されている。
タカ
タカ師匠主な処理は3つ。①connect() でつながりを作る、②conn.cursor() で取っ手を作る、③curs.execute(stmt) で SQL を実行する。
1

connect()

データベースとのつながりを作ります。ここで場所（ファイル名など）を指定します。

2

conn.cursor()

問い合わせを実行し、結果を取り出すための取っ手を作ります。

3

curs.execute(stmt, params)

SQL を実行します。値は SQL の中に直接書かず、別に渡します。

4

curs.fetch*()

取得の場合は、結果の行をここで受け取ります。

保存・更新・削除の場合は、影響した行数などで結果を確かめます。

パラメータ指定の5スタイル

種類SQL の書き方渡す値形
疑問符name=? or country=?(name, country)順番でそろえる
数値name=:0 or country=:1(name, country)順番でそろえる
形式name=%s or country=%s(name, country)順番でそろえる
名前付きname=:name or country=:country{"name": name, "country": country}名前でそろえる
名前付き（別記法）name=%(name)s or country=%(country)s{"name": name, "country": country}名前でそろえる
タカ
タカ師匠最初の3つは並び順でそろえる形、最後の2つは名前でそろえる形だ。すべての接続部品が全部の書き方に対応しているわけではない。

名前でそろえる書き方の例です。SQL の中の :name と、渡す側の項目名が対応します。

コードを見る（1行ずつ説明つき）
# SQL の文。値を直接書かず、コロン付きの目印を置いておく。
# select * は「全部の項目を選ぶ」、where 以降が絞り込みの条件。
stmt = "select * from creature where name=:name or country=:country"
# 目印に入れる値を、項目名と値の組み合わせで用意する。
params = {"name": "Yeti", "country": "US"}
# 文と値を別々に渡す。こう書くと、値に SQL の記号が含まれていても
# 「ただの文字」として扱われるので、意図しない操作をされる心配がない。
curs.execute(stmt, params)
# --- この実行で起きること ---
# 名前が Yeti、または国が US の行が選ばれ、取り出せる状態になる。

取り出しの3つの方法

1️⃣

fetchone()

1件分を返します。無ければ「無い」を表す値が返ります。

🔢

fetchall()

該当するすべてを返します。

📦

fetchmany(num)

指定した件数を上限として返します。

🔎 具体例：値を直接つなげると何が起きるか

"select * from creature where name='" + name + "'" のように文字をつなげて SQL を作ったとします。ここで name に x'; delete from creature; -- という文字が入力されると、SQL は「x を探す」＋「全部削除する」という2つの命令になります。表の中身が全部消えます。

execute(stmt, params) の形で別に渡せば、この文字列は「そういう名前を探す」という条件として扱われるだけで、命令としては解釈されません。該当が無いので何も起きません。

💡 なぜこれが必要か／これを知ったらできること

  • 入力から不正な操作をされないための基本（値を別に渡す）が身につく
  • Python からデータベースを操作する共通の型が分かる

✅ この項のまとめ

  • DB-API = Python 標準の、データベースの共通の呼び出し方
  • 主な処理: connect / cursor / execute / fetch*
  • 値の渡し方は5通り。名前でそろえる形が読みやすい
  • 取得の結果: fetchone / fetchall / fetchmany

SQLiteサーバのいらないデータベース

要するに：SQLite は専用のサーバを持たないデータベースです。Python 標準の sqlite3 で扱えます。

タカ
タカ師匠Python の標準のパッケージには sqlite3 が含まれていて、SQLite に対応している。
タカ
タカ師匠SQLite は特殊だ。独立したデータベースのサーバを持たない。処理はライブラリの中にあり、保存先は1つのファイルの中。他のデータベースは独立したサーバを動かして、通信でやり取りする。
タカ
タカ師匠本書では SQLite をサイトの最初の保存先にする。第14章で表形式のもの・そうでないもの、SQLAlchemy、ORM などをやる。
タカ
タカ師匠データの形をデータベース上でどう表すかを決める必要がある。これまで Creature と Explorer という単純で似た形を使ってきた。これからいろいろ考えていくと、形も変わっていく。
📁

SQLite

サーバを起動する必要がありません。1つのファイルがそのままデータベースです。学習や小さなアプリに向きます。

🖥️

他のデータベース

独立したサーバを動かし、通信でやり取りします。多人数での同時利用に向きます。

最初の版です。接続、表の作成、変換の道具、そして6つの処理が並びます。

コードを見る（1行ずつ説明つき）
# SQLite を扱うための標準の機能を取り込む。
import sqlite3
# データの形を取り込む。
from model.creature import Creature

# cryptid.db というファイルにつなぐ。無ければ新しく作られる。
# check_same_thread=False は、複数の処理から同じつながりを使えるようにする指定。
conn = sqlite3.connect("cryptid.db", check_same_thread=False)
# 問い合わせを実行するための取っ手を作る。
curs = conn.cursor()

# 表を用意する処理。
def init():
    # create table は表を作る命令。if not exists は「すでにあれば何もしない」という指定。
    # これが無いと、2回目の起動で「すでにある」という失敗になる。
    # name text primary key は「name は文字で、1件を特定する項目。重複できない」という意味。
    curs.execute("""create table if not exists creature(
        name text primary key,
        country text,
        area text,
        description text,
        aka text)""")

# データベースから返る「並び」を、プログラムで扱う形に変換する処理。
def row_to_model(row: tuple) -> Creature:
    # 並びの中身を、左から順に5つの名前に取り分ける。
    name, country, area, description, aka = row
    # 取り分けた値で、決めておいた形のデータを組み立てて返す。
    return Creature(name=name, country=country, area=area,
                    description=description, aka=aka)

# 逆に、プログラムの形を、名前でそろえる渡し方に合う形へ変換する処理。
def model_to_dict(creature: Creature) -> dict:
    # 中身があれば項目名と値の組み合わせに変換し、無ければ None を返す。
    return creature.dict() if creature else None

# 名前を指定して1件を取得する。
def get_one(name: str) -> Creature:
    # 名前が一致する行を選ぶ問い合わせ。値は目印にしておく。
    qry = "select * from creature where name=:name"
    # 目印に入れる値を用意する。
    params = {"name": name}
    # 問い合わせを実行する。
    curs.execute(qry, params)
    # 1件を取り出して、扱いやすい形に変換して返す。
    return row_to_model(curs.fetchone())

# すべてを取得する。
def get_all() -> list[Creature]:
    # 絞り込みの条件を書かないので、表の全部の行が対象になる。
    qry = "select * from creature"
    curs.execute(qry)
    # 取り出した全部の行を、1件ずつ扱いやすい形に変換して並べ直す。
    return [row_to_model(row) for row in curs.fetchall()]

# 新しく1件を保存する。
def create(creature: Creature) -> Creature:
    # insert into は「新しい行を入れる」命令。値は5つの目印にしておく。
    qry = """insert into creature values
        (:name, :country, :area, :description, :aka)"""
    # 受け取ったデータを、目印に対応する形に変換する。
    params = model_to_dict(creature)
    # 保存を実行する。
    curs.execute(qry, params)
    # 保存された結果を読み直して返す。実際に入った内容を返せる。
    return get_one(creature.name)

# 既存の1件を書き換える。
def modify(name: str, creature: Creature) -> Creature:
    # update は「既にある行を書き換える」命令。set のあとに変える項目を並べる。
    # where で「どの行を書き換えるか」を指定する。これを忘れると全行が書き換わる。
    qry = """update creature
        set country=:country,
            area=:area,
            description=:description,
            aka=:aka
        where name=:name_orig"""
    # 新しい内容を、目印に対応する形に変換する。
    params = model_to_dict(creature)
    # 「元の名前」を追加で入れる。名前そのものを変える場合に、どの行かを見失わないため。
    params["name_orig"] = name
    # 書き換えを実行する。戻り値は使わないので _ という名前に捨てている。
    _ = curs.execute(qry, params)
    # 書き換わった結果を読み直して返す。
    return get_one(creature.name)

# 全体を置き換える。今の段階では、書き換えと同じ処理でよい。
def replace(name: str, creature: Creature) -> Creature:
    return modify(name, creature)

# 1件を削除する。
def delete(name: str) -> bool:
    # delete from は「行を消す」命令。where で対象を指定する。
    qry = "delete from creature where name = :name"
    params = {"name": name}
    res = curs.execute(qry, params)
    # 結果を真偽の値に変換して返す。
    return bool(res)

# このファイルが読み込まれた時点で、表を用意しておく。

仕事にするデータベースの場所を外から渡す

要するに：接続は data/init.py に切り出し、場所は環境変数で指定します。各リソースのファイルは、そこから conn／curs を取り込みます。

タカ
タカ師匠1つ問題がある。このファイルは init() を呼ばないので、他の処理が使う conn や curs が無い。これは設定の問題だ。起動のときにデータベースの情報をどう渡すか？
タカ
タカ師匠選択肢は、①コードに直接書く（いちばん単純だが、層の分け方に反する）、②外から渡す（設定ファイル、環境変数）。
タカ
タカ師匠環境変数は単純で、Twelve-Factor App のような設計の指針でも勧められている。指定されなかった場合の初期値もコードに含められる。テストのときにテスト用のデータベースを指定するのにも使える。

data/init.py

接続を用意する専用のファイルです。場所は環境変数から取り、無ければ決められた場所を使います。

コードを見る（1行ずつ説明つき）
"""SQLite のデータベースを用意する"""
# 環境変数を読むための標準の機能を取り込む。
import os
# ファイルの場所を組み立てるための標準の機能を取り込む。
from pathlib import Path
# SQLite を扱うための標準の機能を取り込む。
import sqlite3

# つながりと取っ手を、このファイルのどこからでも使える名前として先に用意しておく。
# まだ中身は無いので、何も指していない状態にしておく。
conn = None
curs = None

def get_db(name: str | None = None, reset: bool = False):
    """SQLite のファイルにつなぐ"""
    # この処理の中から、上で用意した2つの名前を書き換える、という宣言。
    global conn, curs
    # すでにつながっている場合の扱い。
    if conn:
        # 作り直す指定が無ければ、何もせずに終わる。二重につなぐのを防ぐ。
        if not reset:
            return
        # 作り直す指定があれば、今のつながりを捨てる。
        conn = None
    # 場所が指定されていない場合、既定の場所を組み立てる。
    if not name:
        # 環境変数から場所を読む。設定されていなければ何も返らない。
        name = os.getenv("CRYPTID_SQLITE_DB")
        # このファイルの場所から2つ上の階層を求める。プロジェクトの一番上にあたる。
        top_dir = Path(__file__).resolve().parents[1]
        # その下の db というフォルダを指す。
        db_dir = top_dir / "db"
        # ファイルの名前を決める。
        db_name = "cryptid.db"
        # フォルダとファイル名をつなげて、完全な場所の文字列にする。
        db_path = str(db_dir / db_name)
        # もう一度環境変数を読み、無ければ今組み立てた場所を使う。
        # 第2引数が「設定されていなかったときに使う値」になる。
        name = os.getenv("CRYPTID_SQLITE_DB", db_path)
    # 決まった場所につなぐ。
    conn = sqlite3.connect(name, check_same_thread=False)
    # 問い合わせ用の取っ手を作る。
    curs = conn.cursor()

# このファイルが読み込まれた時点で、1回だけ実行される。
get_db()

class Missing(Exception):

# つながり、取っ手、そして重複の知らせを取り込む。
from .init import conn, curs, IntegrityError
# 自分で定義した2つの知らせを取り込む。
from errors import Missing, Duplicate
# データの形を取り込む。
from model.explorer import Explorer

# 表の作成、変換の処理は前と同じなので省略。

# 1件を取得する。見つからない場合の扱いを追加した。
def get_one(name: str) -> Explorer:
    qry = "select * from explorer where name=:name"
    params = {"name": name}
    curs.execute(qry, params)
    # 1件を取り出す。見つからなければ「無い」が入る。
    row = curs.fetchone()
    # 中身があるかどうかを先に確かめる。
    if row:
        # あれば、扱いやすい形に変換して返す。
        return row_to_model(row)
    else:
        # 無ければ「見つからない」を投げる。文章に名前を含めて分かりやすくする。
        raise Missing(msg=f"Explorer {name} not found")

# 新しく1件を保存する。重複の場合の扱いを追加した。
def create(explorer: Explorer) -> Explorer:
    qry = "insert into explorer values (:name, :country, :description)"
    params = model_to_dict(explorer)
    # try は「この中で失敗が起きるかもしれない」という囲い。
    try:
        curs.execute(qry, params)
    # 決まりに反した場合だけ、この下が動く。
    except IntegrityError:
        # データベース固有の知らせを、アプリの言葉に置き換えて投げ直す。
        raise Duplicate(msg=f"Explorer {explorer.name} already exists")
    # 問題なければ、保存された結果を読み直して返す。
    return get_one(explorer.name)

# 既存の1件を書き換える。対象が無い場合の扱いを追加した。
def modify(name: str, explorer: Explorer) -> Explorer:
    qry = """update explorer
        set country=:country, description=:description
        where name=:name_orig"""
    params = model_to_dict(explorer)
    params["name_orig"] = name
    curs.execute(qry, params)
    # rowcount は「実際に何行が書き換わったか」の数。
    # 1 なら成功、0 なら対象が無かったということ。
    if curs.rowcount == 1:
        return get_one(explorer.name)
    else:
        raise Missing(msg=f"Explorer {name} not found")

# 全体を置き換える。書き換えと同じ処理を使う。
def replace(name: str, explorer: Explorer) -> Explorer:
    return modify(name, explorer)

# 1件を削除する。返す値が無くなったので、戻り値の書き添えも外している。
def delete(name: str):
    qry = "delete from explorer where name = :name"
    params = {"name": name}
    res = curs.execute(qry, params)
    # 1行も消えていなければ、対象が無かったということ。
    if curs.rowcount != 1:
        raise Missing(msg=f"Explorer {name} not found")
タカ
タカ師匠これで「値か、無し」のような戻り値の書き方は不要になる。知らせは誰かが受け止めるまで呼び出しの経路をさかのぼって流れていくので、サービス層は何も変えなくていい。

Web層での変換

受け止めて、外向けの番号に変換します。

コードを見る（1行ずつ説明つき）
# 窓口をまとめる入れ物と、エラーを返すための知らせを取り込む。
from fastapi import APIRouter, HTTPException
# データの形を取り込む。
from model.explorer import Explorer
# サービス層を取り込む。
import service.explorer as service
# 自分で定義した2つの知らせを取り込む。
from errors import Missing, Duplicate

# この中の住所は /explorer から始まる。
router = APIRouter(prefix="/explorer")

# 一覧は失敗しないので、受け止める処理を書いていない。
@router.get("")
@router.get("/")
def get_all() -> list[Explorer]:
    return service.get_all()

# 1件の取得。見つからない場合に備える。
@router.get("/{name}")
def get_one(name: str) -> Explorer:
    try:
        return service.get_one(name)
    # Missing が流れてきたら、その内容を exc という名前で受け取る。
    except Missing as exc:
        # 404（見つからない）に変換して返す。中の文章もそのまま伝える。
        raise HTTPException(status_code=404, detail=exc.msg)

# 作成。成功したときの番号を 201 に指定している。
@router.post("", status_code=201)
@router.post("/", status_code=201)
def create(explorer: Explorer) -> Explorer:
    try:
        return service.create(explorer)
    # すでにある場合の知らせを受け止める。
    except Duplicate as exc:
        raise HTTPException(status_code=404, detail=exc.msg)

# 一部の更新。対象が無い場合に備える。
@router.patch("/{name}")
def modify(name: str, explorer: Explorer) -> Explorer:
    try:
        return service.modify(name, explorer)
    except Missing as exc:
        raise HTTPException(status_code=404, detail=exc.msg)

# 全体の置き換え。同じく対象が無い場合に備える。
@router.put("/{name}")
def replace(name: str, explorer: Explorer) -> Explorer:
    try:
        return service.replace(name, explorer)
    except Missing as exc:
        raise HTTPException(status_code=404, detail=exc.msg)

# 削除。成功したときの番号を 204（成功したが返す中身は無い）にしている。
@router.delete("/{name}", status_code=204)
def delete(name: str):
    try:
        return service.delete(name)
    except Missing as exc:
        raise HTTPException(status_code=404, detail=exc.msg)

直したあと、もう一度確かめます。

コードを見る（1行ずつ説明つき）

データ層

データベース固有の知らせを受け止め、Missing／Duplicate に置き換えて投げる。

アプリの言葉に変換
→

サービス層

何もしない。知らせはそのまま通り抜ける。

変更不要
→

Web層

受け止めて、404 などの番号に変換して返す。

外向けに変換
↺ データベースを別の種類に替えても、変わるのはデータ層の受け止め方だけ。サービス層と Web 層はそのまま使えます。

💡 なぜこれが必要か／これを知ったらできること

  • 「下の層の細部を上に漏らさない」失敗の設計が書ける
  • 返す番号と失敗の対応を整理できる

✅ この項のまとめ

  • 独自の知らせ: Missing, Duplicate
  • データ層で投げ、Web層で番号に変換する
  • 知らせは呼び出しの経路を自由に流れる
  • 戻り値の書き添えは、うまくいった場合だけでよい

単体テストメモリ上のデータベースで確かめる

要するに：メモリ上のデータベース（:memory:）で確認し、fixture で見本のデータを渡し、失敗が起きることも pytest.raises で確かめます。

タカ
タカ師匠単体の確認はデータ層だけを扱い、データベースの呼び出しと SQL の書き方を確かめる。Missing／Duplicate を定義したあとのほうが説明しやすいので、ここに置いた。

データ層のテストです。1行目の順番が重要です。

コードを見る（1行ずつ説明つき）
# 環境変数を設定するための標準の機能を取り込む。
import os
# テスト用の道具を取り込む。
import pytest

# ここが最重要。data を取り込む「前に」場所をメモリ上に指定する。
# :memory: はファイルではなくメモリ上に作る指定で、終了すると消える。
# 順番を逆にすると、init.py が本物のファイルにつないでしまう。
os.environ["CRYPTID_SQLITE_DB"] = ":memory:"

# ここから下で、ようやくデータ層を取り込む。この時点でメモリ上につながる。
from model.creature import Creature
from errors import Missing, Duplicate
from data import creature as code

# この印を付けると、同じ名前を引数に書いたテストに、この結果が渡される。
@pytest.fixture
def sample() -> Creature:
    # テストで使う見本のデータを作って返す。
    return Creature(
        name="Yeti",
        country="CN",
        area="Himalayas",
        description="Hirsute Himalayan",
        aka="Abominable Snowman",
    )

# 引数に sample と書くだけで、上の見本が渡ってくる。
def test_create(sample):
    # 見本を保存する。
    resp = code.create(sample)
    # 保存された結果が、渡したものと同じであることを確かめる。
    assert resp == sample

# 同じものを2回保存したときの動きを確かめる。
def test_create_duplicate(sample):
    # この中で Duplicate が起きることを期待する、という書き方。起きなければ失敗になる。
    with pytest.raises(Duplicate):
        # 戻り値は使わないので _ に捨てている。
        _ = code.create(sample)

# 保存したものを取得できるか確かめる。
def test_get_one(sample):
    resp = code.get_one(sample.name)
    assert resp == sample

# 無いものを取得したときの動きを確かめる。
def test_get_one_missing():
    # Missing が起きることを期待する。
    with pytest.raises(Missing):
        _ = code.get_one("boxturtle")

# 書き換えができるか確かめる。
def test_modify(sample):
    # 見本の国を JP に変えてみる。
    sample.country = "JP"
    # その内容で書き換える。
    resp = code.modify(sample.name, sample)
    # 書き換えた内容が反映されていることを確かめる。
    assert resp == sample

# 無いものを書き換えようとしたときの動きを確かめる。
def test_modify_missing():
    # 保存されていない、でたらめなデータを用意する。
    bogus = Creature(name="bogus", country="CA", area="", description="", aka="")
    with pytest.raises(Missing):
        _ = code.modify(bogus.name, bogus)

# 削除ができるか確かめる。
def test_delete(sample):
    resp = code.delete(sample.name)
    # 削除の処理は何も返さないので、返り値は「無い」になる。
    assert resp is None

# すでに消したものを、もう一度消そうとしたときの動きを確かめる。
def test_delete_missing(sample):
    with pytest.raises(Missing):
        _ = code.delete(sample.name)
# --- 実行結果 ---
# 8 passed
タカ
タカ師匠ポイントは4つ。①data を取り込む前に 環境変数を ":memory:" にする。これで SQLite は完全にメモリ上で動き、既存のファイルを壊さない。data/init.py は最初に取り込まれたときにこれを確認する。
タカ
タカ師匠②sample という名前の準備の仕組みが、Creature を必要とするテストに渡される。
タカ
タカ師匠③テストは上から順に実行される。同じデータベースが立ち上がったままで、テストの間で作り直されない。前のテストの変更を残すためだ。準備の仕組みの作り直しの範囲は2種類ある。テストごと（初期値）：各テストの前に新しく作られる。全体で1回：最初の1回だけ作られる。
タカ
タカ師匠④いくつかのテストは Missing や Duplicate をわざと起こさせて、受け止められることを確かめている。つまり、各テストは sample という新しい Creature を受け取る。
タカ
タカ師匠ヒント：test/unit/data/test_explorer.py の自作版も作れる。

🔎 具体例：取り込みの順番を間違えると

環境変数の設定を from data import creature より後に書いたとします。すると data/init.py はすでに実行済みで、本物の cryptid.db につながっています。その後に環境変数を設定しても、つながりは作り直されません。

結果として、テストが本物のデータベースに書き込み、test_delete が実際のデータを消します。テストを1回動かすたびに、開発中のデータが変わっていきます。だから設定は必ず取り込みより前に書きます。

💡 なぜこれが必要か／これを知ったらできること

  • ファイルを汚さずにデータベースの確認ができる
  • 準備の仕組みと、その作り直しの範囲の使い分けが分かる
  • 失敗が起きることを確かめるテストが書ける

✅ この項のまとめ

  • CRYPTID_SQLITE_DB=":memory:" でメモリ上のデータベース
  • 準備の仕組みで見本のデータを渡す
  • 作り直しの範囲: テストごと（初期値）／全体で1回
  • pytest.raises(Missing) で失敗の確認

第1問DB-API の基本

Python の DB-API の基本的な流れを、4つの段階で説明してください。それぞれの段階で何を行うかも併せてどうぞ。

✅ 解答例
①connect() でデータベースとのつながりを作る、②conn.cursor() で SQL を実行するための取っ手を作る、③curs.execute(stmt, params) で SQL を実行、④取得の場合は curs.fetchone() / fetchall() / fetchmany(n) で結果を取り出す。保存・更新・削除の場合は、実行の戻り値や rowcount で結果を確認する。
📝 採点ポイント
□ connect → cursor → execute → fetch* の流れを述べている
□ 実行に渡すもの（文と値）に触れている
□ 取得と、保存・更新・削除での結果の確かめ方の違いに触れている
第2問環境変数による設定

本書ではデータベースの場所をコードに直接書かず、環境変数から取得しています。なぜでしょうか？「Twelve-Factor App」という言葉も含めて説明してください。

✅ 解答例
設定をコードと分けることで、本番・開発・テストで違うデータベースを使い分けられるから。コードを変えずに動きを変えられるのは Twelve-Factor App の原則の一つ。また、テストでは :memory: を指定してメモリ上のデータベースにすることで、ファイルを汚さない確認も書ける。大事な情報を保管場所に入れずに済む、という安全上の利点もある。
📝 採点ポイント
□ 環境ごとの切り替えに触れている
□ Twelve-Factor App の設定の原則に言及
□ テストでの活用（:memory: など）に触れている
第3問末尾スラッシュ問題

/explorer と /explorer/ の両方で同じ返事を返すには、FastAPI でどう書きますか？

✅ 解答例
1つの処理に複数のデコレータを付ける。たとえば @router.get("") と @router.get("/") を同じ処理 get_all() の上に両方書く。これで APIRouter(prefix="/explorer") と組み合わさり、/explorer と /explorer/ の両方を受け付ける。
📝 採点ポイント
□ デコレータを重ねる手法を述べている
□ "" と "/" の両方を指定する例を示している
□ APIRouter(prefix=...) との組み合わせに触れている
第4問独自の知らせで層を越える

「データが見つからない」「データが重複している」という失敗を、データ層から Web層まで安全に伝える設計を説明してください。なぜ単に「値か、無し」を返すのではだめなのですか？

✅ 解答例
Missing と Duplicate という独自の知らせ（アプリ固有で、データベース固有ではない）を定義し、データ層で投げる。知らせは誰かが受け止めるまで呼び出しの経路を自由に流れるので、サービス層は変更が不要。Web層で受け止めて 404 などに変換する。「値か、無し」だと「なぜ失敗したか」が表せず（見つからない？ 権限が足りない？ つながらない？）、全部の処理の戻り値の書き添えを直す必要があり、各層で「無いかどうか」を確かめる行も増える。知らせを使えば、書き添えはうまくいった場合だけでよく、失敗の扱いを1か所にまとめられる。
📝 採点ポイント
□ 独自の知らせを定義する設計を述べている
□ 知らせが経路を流れる利点に触れている
□ 「値か、無し」の問題点（理由が表せない、直す量が多い）を指摘
第5問メモリ上のデータベースでのテスト

pytest でデータベースを使った単体テストを書くとき、SQLite の :memory: をどう活用しますか？ テストが失敗しがちな落とし穴も含めてどうぞ。

✅ 解答例
テストファイルの先頭で os.environ["CRYPTID_SQLITE_DB"] = ":memory:" を設定してから data を取り込むと、SQLite は完全にメモリ上で動き、既存のファイルを壊さない。落とし穴は「data を先に取り込んでしまうと、init.py が既存の場所でつながりを作ってしまう」こと。環境変数の設定は必ず取り込みの前に書く。また、準備の仕組みの作り直しの範囲は初期値がテストごとなので、状態が引き継がれない。順番に依存させたいなら全体で1回の範囲を使うか、状態の扱いを意識して設計する。
📝 採点ポイント
□ :memory: の指定方法に触れている
□ 環境変数を設定するタイミング（取り込みの前）に言及している
□ 準備の仕組みの範囲の違い（テストごと と 全体で1回）に触れている
