ウェブ web

インターネットを通じて、画面や情報をやり取りする仕組み全体のこと。ブラウザで見るページも、スマホアプリが裏側で情報を取りにいく通信も、どちらもウェブに含まれます。

Python パイソン

プログラムを書くための言葉のひとつ。英語に近い書き方で読みやすく、Webサービスからデータ分析まで幅広く使われています。

FastAPI ファストAPI

Python で「ほかのプログラムから呼び出せる窓口」を作るための道具一式。少ない記述で、速く動き、入力の間違いも自動でチェックしてくれます。

フレームワーク framework

よく作るものの骨組みがあらかじめ用意された道具一式。ゼロから全部書かずに、決まった場所に自分の処理を書き足すだけで動きます。

API

プログラムが別のプログラムに用件を伝えて、答えを受け取るための窓口。人が画面で操作する代わりに、機械同士が決まった形式でやり取りします。

サービス service

ひとつの役目を持って動き続けているプログラム。たとえば「ユーザー情報を管理する担当」「決済を扱う担当」のように役割ごとに分けて動かします。

並行処理 concurrency

たくさんの依頼が同時に来ても、待ち時間の間に別の依頼を進めることで、全体を止めずに処理するやり方。

レイヤード・アーキテクチャ 層構造

プログラムを「外からの受け付け」「中身の判断」「データの保存」のように役割ごとの階層に分けて作る設計。どこを直せばいいかが分かりやすくなります。

ビッグデータ

1台のパソコンでは扱いきれないほど大量のデータ。保存の仕方も、集計の仕方も、少量のときとは別のやり方が必要になります。

バックエンド／フロントエンド

フロントエンドは利用者が直接見て触る画面の側。バックエンドは画面の裏でデータを保存したり計算したりしている側です。

生産性が高い

同じものを作るのにかかる時間が短い、という意味。この本では「短い時間で、ちゃんと動くものが作れる」ことを指します。

データソース

プログラムが読み書きする情報の出どころ。この本のパートIVでは、全部の例が同じ情報の出どころ（想像上の生き物のデータ）を使います。

第3問なぜ最初に「現代のウェブ」を学ぶのか

なぜいきなり FastAPI のコードを書き始めるのではなく、第1章で「現代のウェブ」の概観から入るのですか？ 理由を自分の言葉で説明してください。

✅ 解答例
FastAPI は「現代のウェブが抱える課題」を解くために設計されたフレームワークなので、その課題を知らないと、なぜ FastAPI がこういう作りなのかが理解できない。土台を理解せずに道具だけ学ぶと、応用が利かず、ちょっとした問題で詰まる。だから先にウェブそのものの今を押さえる。
📝 採点ポイント
□ FastAPI が「課題を解くための道具」であると説明している
□ 課題を知らないと道具の意味がわからない、という論理に触れている
□ 応用力・問題解決力に関する言及がある
