要するにこの章を5行で

間奏曲：認証は必要か？完全に匿名では何が困るか

要するに：認証が必要な場面は多くあります。完全に匿名だと、攻撃にも計測にも弱くなります。HTTPS も必須です。

タカ
タカ師匠認証は「あなたは誰なのか」という話だ。秘密の情報を、その人だけを表すものに結びつける必要がある。
ハル
ハル全部のページを誰でも見られるようにしてはダメですか？
タカ
タカ師匠できなくはない。けど、大量の問い合わせを送りつけて使えなくする攻撃にさらされる。受け付ける数の上限は Web サーバの外でも設定できる（第13章）けど、ほぼすべての公開された窓口の提供者は、最低限の確認を求めている。
タカ
タカ師匠安全のためだけじゃなく、「サイトがどれだけ役に立っているか」も知りたい。①何人が使ったか、②よく見られているページ、③変更後に利用が増えたか、④よくある閲覧の順番。これらの答えには、それぞれの訪問者の確認が要る。
タカ
タカ師匠注意。確認が必要なサイトは、必ず HTTPS を使うべきだ。暗号化しない通信では、秘密の情報が途中で読み取られる。HTTPS の設定は第13章で扱う。

⚠️ HTTPS が必須である理由

暗号化されていない通信では、送った内容が途中の経路でそのまま読めます。名前とパスワードを送れば、それがそのまま見えます。同じ無線ネットワークにいる人が見られる場合もあります。身分の確認を行うサイトでは、HTTPS は選択肢ではなく前提です。

✅ この項のまとめ

  • 認証 = 身分の確認
  • 公開された窓口には、最低限の確認が必要
  • 利用状況を数える目的でも認証は役に立つ
  • 認証・認可を行うなら HTTPS は必須

グローバル認証：共有シークレットいちばん単純な方法

要するに：HTTP Basic は単純ですが、合言葉を全員で共有する形なので、個別の利用者を見分けられません。学習用には向きますが、本番には向きません。

タカ
タカ師匠いちばん単純な確認は、サーバだけが知っている合言葉を渡すことだ。一致すれば確認成功。暗号化されていないと、途中で読み取られる。
タカ
タカ師匠新しく auth.py を作る。main.py とは別のサーバを立てるので、他のサーバが動いていないか確認しよう。

まず、送られた名前とパスワードをそのまま返すだけの窓口です。まだ何も確認していません。

コードを見る（1行ずつ説明つき）
# サーバを動かす道具を取り込む。
import uvicorn
# 枠組み本体と、依存関係、エラー、番号の定義を取り込む。
from fastapi import FastAPI, Depends, HTTPException, status
# 名前とパスワードを決まった形で受け取るための部品を取り込む。
from fastapi.security import HTTPBasic, HTTPBasicCredentials

# アプリ全体を作る。
app = FastAPI()
# 名前とパスワードを取り出す仕組みを1つ用意する。
basic = HTTPBasic()

# /who への GET を、この下の処理に結びつける。
@app.get("/who")
# Depends で包むことで、送られてきた名前とパスワードが creds に入ってくる。
def get_user(creds: HTTPBasicCredentials = Depends(basic)) -> dict:
    # 受け取った内容をそのまま返す。この時点では正しいかどうかを見ていない。
    return {"username": creds.username, "password": creds.password}

# 直接動かされたときだけサーバを起動する。
if __name__ == "__main__":
    uvicorn.run("auth:app", reload=True)

$ http -q -a me:secret localhost:8000/who

タカ師匠自動で作られる説明ページ（/docs）でも試せる。右の下向き矢印 → Try It Out → Execute、で名前とパスワードの入力欄が出る。何を入れても送信できる。
タカ
タカ師匠今のコードは「送られたものをそのまま返す」だけで、何も確認していない。次は合言葉を1組だけ持たせて、それと一致するか確かめる。

決められた組み合わせと一致するかを確かめる版です。

コードを見る（1行ずつ説明つき）
# サーバを動かす道具を取り込む。
import uvicorn
# 枠組み本体、依存関係、エラー、番号の定義を取り込む。
from fastapi import FastAPI, Depends, HTTPException, status
# 名前とパスワードを受け取る部品を取り込む。
from fastapi.security import HTTPBasic, HTTPBasicCredentials

# アプリ全体を作る。
app = FastAPI()
# 名前とパスワードを取り出す仕組みを用意する。
basic = HTTPBasic()

# 正解の組み合わせをコードの中に置いておく。学習用の書き方で、本番では避ける。
SECRET_USER = "newphone"
SECRET_PASSWORD = "whodis?"

# /who への GET を結びつける。
@app.get("/who")
def get_user(creds: HTTPBasicCredentials = Depends(basic)) -> dict:
    # 名前とパスワードの両方が正解と一致するかを確かめる。and は「両方とも」の意味。
    if creds.username == SECRET_USER and creds.password == SECRET_PASSWORD:
        # 一致すれば内容を返す。
        return {"username": creds.username, "password": creds.password}
    # 一致しなければ 401（まだ身分が確認できていない）を返す。
    raise HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Hey!",
    )

# 直接動かされたときだけサーバを起動する。
if __name__ == "__main__":
    uvicorn.run("auth:app", reload=True)
タカ
タカ師匠補足：HTTP_401_UNAUTHORIZED は FastAPI の番号の定義から取り込める。401 は正式には「Unauthorized（許可されていない）」だけど、実際の意味は「まだ身分が確認できていない」だ。

間違った組み合わせと、正しい組み合わせの両方を試します。

コードを見る（1行ずつ説明つき）
# 正解ではない組み合わせを送ってみる。
$ http -a me:secret localhost:8000/who
# --- 実行結果 ---
# HTTP/1.1 401 Unauthorized
# content-type: application/json
#
# {
#     "detail": "Hey!"
# }

# 正解の組み合わせを送ってみる。
$ http -q -a newphone:whodis? localhost:8000/who
# --- 実行結果 ---
# {
#     "password": "whodis?",
#     "username": "newphone"
# }
# 一致したので、内容が返ってきた。

⚠️ この方法の限界

合言葉が1組しかないので、「誰が使ったか」を区別できません。10人で共有すれば、10人全員が同じ扱いになります。1人だけ利用を止めたい場合、合言葉を変えるしかなく、残り9人にも影響します。またパスワードをそのまま返している点も、実際のサービスでは避けます。

💡 なぜこれが必要か／これを知ったらできること

  • FastAPI で HTTP Basic を使う方法が分かる
  • 名前とパスワードを依存性注入で受け取る書き方が身につく
  • 401 の意味が「まだ確認できていない」だと正しく理解できる

✅ この項のまとめ

  • HTTPBasic() を Depends() で渡す
  • HTTPException(401) で確認の失敗を返す
  • 共有の合言葉では、個別の利用者を見分けられない

シンプルな個人認証8つの手順

要するに：個別の確認は、利用者の表にハッシュ化したパスワードを保存し、HTTPS で送り、ハッシュ同士を比べるのが基本です。

タカ
タカ師匠前の節のやり方は大ざっぱで、安全ではないし、個人を見分けられない。多くのサイトは、①個別の訪問者を定義する、②特定の窓口へのアクセスを特定の訪問者に結びつける（認証）、③一部の窓口や訪問者に違う権限を割り当てられるようにする（認可）、④訪問者ごとの情報（興味、購入の記録など）を保存する、ことを望む。
タカ
タカ師匠訪問者が人なら名前・メール・パスワード、外部のプログラムなら APIキーと秘密の文字列を使う。

本物の個人認証の手順

1

名前とパスワードを送る

問い合わせに添える情報としてサーバに送る。

2

HTTPS で守る

途中で読み取られないよう暗号化する。

3

パスワードをハッシュ化する

元に戻せない別の文字列に変換する。ハッシュから元のパスワードは復元できない。

4

表に保存する

名前とハッシュ化したパスワードを保存する。

元のパスワードそのものは、絶対に保存しない。

5

次回も同じ方式でハッシュ化して比べる

入力された文字を同じ方式で変換し、保存済みのものと比べる。

6

一致したら利用者の情報を渡す

一致しなければ「無い」を返すか、失敗を投げる。

7

サービス層で記録を残す

関連する数値や記録を作る。

8

Web層で必要な処理に渡す

確認済みの利用者の情報を、それを必要とする処理に渡す。

🔎 具体例：ハッシュ化していると何が守られるか

保存されている値が $2b$12$KIXQ... のような文字列だとします。この値を見ても、元のパスワードが hello123 だったのかどうかは分かりません。変換は一方向で、逆向きに計算する方法が用意されていないからです。

ログインのときは、入力された hello123 を同じ方式で変換し、保存されている文字列と一致するかを比べます。一致すれば本人と判断できます。元のパスワードをどこにも保存せずに、確認だけができます。

✅ この項のまとめ

  • 利用者の表（名前 + ハッシュ化したパスワード）
  • パスワードは保存の前にハッシュ化
  • HTTPS で読み取りを防ぐ
5

よりファンシーな個人認証OAuth2 + JWT を層ごとに作る

要するに：個別の確認は OAuth2 + JWT + bcrypt が現代の基本です。外部のサービスで身分を確認する場合は OIDC を使います。

タカ
タカ師匠本章では FastAPI の公式の説明とは逆に、データ層から上に登っていく。

OAuth2

タカ
タカ師匠OAuth 2.0 は、あるサイトやアプリが、利用者に代わって別のサービスの情報にアクセスできるようにするための取り決めだ。
タカ
タカ師匠昔は、B のログイン名とパスワードを A に教えて、A があなたの B の情報にアクセスする、ということがあった。これは続かず、OAuth が定められた。
タカ
タカ師匠OAuth2 はよく使われるが複雑な権限の取り決めだ。いくつかの手順の型がある。本章では認可コードの型を使う。

必要なパッケージを3つ入れます。

ユーザモデル

保存する形は2項目だけです。項目名が password ではないことに注目してください。

コードを見る（1行ずつ説明つき）

ユーザ・データ層

利用者用の表と、削除済みを移す表の2つを用意します。

コードを見る（1行ずつ説明つき）
# つながり、取っ手、重複の知らせを取り込む。
from .init import conn, curs, IntegrityError
# 自分で定義した2つの知らせを取り込む。
from errors import Missing, Duplicate
# 利用者の形を取り込む。
from model.user import User

# 今使っている利用者の表。無ければ作る。
curs.execute("""create table if not exists user(
    name text primary key,
    hash text)""")

# 削除済みの利用者を移しておく表。項目は同じ。
curs.execute("""create table if not exists xuser(
    name text primary key,
    hash text)""")

# データベースから返る並びを、扱いやすい形に変換する。
def row_to_model(row: tuple) -> User:
    # 0番目が名前、1番目がハッシュ。
    return User(name=row[0], hash=row[1])

# 形を、渡し方に合う形へ変換する。
def model_to_dict(user: User) -> dict:
    return user.dict() if user else None

# 名前を指定して1件を取得する。
def get_one(name: str) -> User:
    qry = "select * from user where name=:name"
    params = {"name": name}
    curs.execute(qry, params)
    row = curs.fetchone()
    if row:
        return row_to_model(row)
    else:
        # 見つからなければ「見つからない」を投げる。
        raise Missing(msg=f"User {name} not found")

# すべてを取得する。
def get_all() -> list[User]:
    qry = "select * from user"
    curs.execute(qry)
    return [row_to_model(row) for row in curs.fetchall()]

# 新しく1件を保存する。
def create(user: User) -> User:
    # 入れる項目名を明示して書いている。表の項目が増えたときに壊れにくい。
    qry = "insert into user (name, hash) values (:name, :hash)"
    params = model_to_dict(user)
    try:
        curs.execute(qry, params)
    # 同じ名前がすでにある場合の知らせを受け止める。
    except IntegrityError:
        raise Duplicate(msg=f"User {user.name} already exists")
    return get_one(user.name)

# 既存の1件を書き換える。
def modify(name: str, user: User) -> User:
    qry = "update user set name=:name, hash=:hash where name=:name_orig"
    params = model_to_dict(user)
    # どの行かを見失わないよう、元の名前を追加で入れる。
    params["name_orig"] = name
    curs.execute(qry, params)
    # 1行だけ書き換わったかを確かめる。
    if curs.rowcount == 1:
        return get_one(user.name)
    else:
        raise Missing(msg=f"User {name} not found")

# 1件を削除する。ただし完全には消さず、別の表に移す。
def delete(name: str):
    # 消す前に、内容を読んでおく。あとで移すために必要。
    user = get_one(name)
    qry = "delete from user where name = :name"
    params = {"name": name}
    res = curs.execute(qry, params)
    # 1行も消えていなければ、対象が無かったということ。
    if curs.rowcount != 1:
        raise Missing(msg=f"User {name} not found")
    # 読んでおいた内容を、削除済み用の表に入れる。記録を残すため。
    qry = "insert into xuser (name, hash) values (:name, :hash)"
    curs.execute(qry, model_to_dict(user))
タカ
タカ師匠補足。このコードは user（利用中）と xuser（削除済み）の2つの表を作る。よくある作りは、利用者の表に「削除済みかどうか」の項目を足すやり方だけど、私は別の表に移す方式を採る。理由は2つ。①すべての問い合わせで「削除済みでないこと」の確認を繰り返さなくて済む、②問い合わせが速くなる。「はい／いいえ」のように値の種類が少ない項目には、索引が効きにくい。

ユーザ・サービス層

ハッシュ化、照合、トークンの作成と読み取りが集まる場所です。

コードを見る（1行ずつ説明つき）
# 日時と、時間の長さを扱う標準の機能を取り込む。有効期限の計算に使う。
from datetime import datetime, timedelta
# JWT を作ったり読んだりする機能を取り込む。
from jose import jwt
# パスワードのハッシュ化と照合を行う機能を取り込む。
from passlib.context import CryptContext
# 利用者の形、データ層、知らせを取り込む。
from model.user import User
from data import user as data
from errors import Missing

# 署名に使う秘密の文字列。これが漏れると、誰でも正しい見た目のトークンを作れてしまう。
# 本番では、コードに書かずに環境変数から読む。
SECRET_KEY = "keep-it-secret-keep-it-safe"
# 署名に使う計算の方式。
ALGORITHM = "HS256"
# トークンが有効な時間（分）。短いほど、漏れたときの影響が小さい。
ACCESS_TOKEN_EXPIRE_MINUTES = 15

# ハッシュ化の設定を1つ用意する。bcrypt という方式を使う指定。
# deprecated="auto" は、古い方式が見つかったら自動で新しい方式に移す設定。
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# 入力されたパスワードが、保存されているハッシュと合っているかを確かめる。
def verify_password(plain: str, hash: str) -> bool:
    # 入力を同じ方式で変換して比べる。合っていれば真、違えば偽を返す。
    return pwd_context.verify(plain, hash)

# 入力されたパスワードを、保存用のハッシュに変換する。
def get_hash(plain: str) -> str:
    return pwd_context.hash(plain)

# トークンの中から利用者の名前を取り出す。
def get_jwt_username(token: str) -> str | None:
    try:
        # 秘密の文字列を使って中身を読み取る。署名が合わなければここで失敗する。
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        # sub という項目に、利用者の名前を入れる決まりにしている。
        return payload.get("sub")
    # 読み取れなかった場合（改ざん、期限切れなど）は「無い」を返す。
    except jwt.JWTError:
        return None

# トークンから、実際の利用者の情報を取り出す。
def get_current_user(token: str) -> User | None:
    # まず名前を取り出す。
    name = get_jwt_username(token)
    # 取り出せなければ、それ以上進まない。
    if not name:
        return None
    try:
        # 名前でデータ層から探す。
        return lookup_user(name)
    # 削除済みなどで見つからない場合は「無い」を返す。
    except Missing:
        return None

# 名前で利用者を探す。
def lookup_user(name: str) -> User | None:
    return data.get_one(name)

# 名前とパスワードで本人かどうかを確かめる。
def auth_user(name: str, plain: str) -> User | None:
    try:
        # まず名前で探す。
        user = lookup_user(name)
        # 見つかり、かつパスワードも合っていれば、その利用者を返す。
        if user and verify_password(plain, user.hash):
            return user
    # 見つからない場合は、何もせず下に進む。
    except Missing:
        pass
    # 名前が無い場合も、パスワードが違う場合も、同じ「無い」を返す。
    # どちらが原因かを外に伝えないことで、名前を推測されにくくする。
    return None

# トークンを作る。
def create_access_token(data_: dict, expires: timedelta | None = None):
    # 渡された内容を写し取る。元のものを書き換えないため。
    src = data_.copy()
    # 現在の時刻を取得する。
    now = datetime.utcnow()
    # 有効期間が指定されていなければ、15分を使う。
    if not expires:
        expires = timedelta(minutes=15)
    # exp という項目に、いつまで有効かを入れる。読み取る側はこれを見て期限切れを判断する。
    src["exp"] = now + expires
    # 秘密の文字列で署名して、1つの文字列にまとめる。
    encoded_jwt = jwt.encode(src, SECRET_KEY, algorithm=ALGORITHM)
    return encoded_jwt

# ここから下は、データ層に渡すだけの処理。
def get_one(name: str) -> User:
    return data.get_one(name)

def get_all() -> list[User]:
    return data.get_all()

def create(user: User) -> User:
    return data.create(user)

def modify(name: str, user: User) -> User:
    return data.modify(name, user)

def delete(name: str):
    return data.delete(name)

⚠️ 秘密の文字列の扱い

上の SECRET_KEY は、コードの中に直接書いてあります。これは説明のための書き方で、本番では避けます。この文字列を知っている人は、正しい見た目のトークンを自由に作れてしまうためです。第10章で学んだように、環境変数から読む形にして、コードの保管場所には入れません。

ユーザ・Web層

ログインの窓口と、トークンを確認する窓口です。

コードを見る（1行ずつ説明つき）
# 時間の長さを扱う機能を取り込む。
from datetime import timedelta
# 窓口のまとめ、依存関係、エラー、番号の定義を取り込む。
from fastapi import APIRouter, Depends, HTTPException, status
# トークンを受け取る部品と、ログイン用の入力欄を受け取る部品を取り込む。
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
# 利用者の形、サービス層、知らせを取り込む。
from model.user import User
import service.user as service
from errors import Missing, Duplicate

# トークンが有効な時間（分）。
ACCESS_TOKEN_EXPIRE_MINUTES = 15
# この中の住所は /user から始まる。
router = APIRouter(prefix="/user")
# 「トークンを受け取る」仕組みを用意する。tokenUrl は、トークンを発行する窓口の住所。
# 説明ページの画面が、この住所を使ってログインの入力欄を表示する。
oauth2_dep = OAuth2PasswordBearer(tokenUrl="/user/token")

# 確認に失敗したときの返し方を、1か所にまとめておく。
def unauthed():
    raise HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        # 名前とパスワードのどちらが違うかは伝えない。推測されにくくするため。
        detail="Incorrect username or password",
        # 「この方式で身分を示してください」と相手に伝える添え情報。
        headers={"WWW-Authenticate": "Bearer"},
    )

# ログインの窓口。ここでトークンを発行する。
@router.post("/token")
# Depends() だけを書くと、名前とパスワードの入力欄の内容が form_data に入る。
async def create_access_token(
    form_data: OAuth2PasswordRequestForm = Depends(),
):
    # 名前とパスワードで本人かどうかを確かめる。
    user = service.auth_user(form_data.username, form_data.password)
    # 確認できなければ、401 を返してここで終わる。
    if not user:
        unauthed()
    # 有効期間を計算する。
    expires = timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    # 利用者の名前を sub という項目に入れて、トークンを作る。
    access_token = service.create_access_token(
        data_={"sub": user.name}, expires=expires
    )
    # 作ったトークンと、その添え方の種類を返す。
    return {"access_token": access_token, "token_type": "bearer"}

# 送られてきたトークンをそのまま返すだけの、確認用の窓口。
@router.get("/token")
# Depends(oauth2_dep) と書くと、添えられたトークンが取り出されて token に入る。
# トークンが無い場合は、この処理に入る前に 401 が返る。
def get_access_token(token: str = Depends(oauth2_dep)) -> dict:
    return {"token": token}

# ここから下は、利用者の作成・取得などの窓口。
@router.get("/")
def get_all() -> list[User]:
    return service.get_all()

@router.get("/{name}")
def get_one(name: str) -> User:
    try:
        return service.get_one(name)
    except Missing as exc:
        raise HTTPException(status_code=404, detail=exc.msg)

@router.post("/", status_code=201)
def create(user: User) -> User:
    try:
        return service.create(user)
    # すでにある場合は 409（すでにあるものと衝突）を返す。
    except Duplicate as exc:
        raise HTTPException(status_code=409, detail=exc.msg)

⚠️ 中身は「読めるが、書き換えられない」

JWT の中身は暗号化されていません。誰でも変換を戻して読めます。だから、見られて困る情報（パスワード、個人を特定する詳細な情報）は入れません。

一方で、中身を書き換えると署名が合わなくなり、サーバ側で読み取るときに失敗します。つまり「読めるが、書き換えられない」という性質です。

🔎 具体例：取り消しが効かないとはどういうことか

ある利用者を、管理画面から削除したとします。しかしその人が5分前に受け取ったトークンは、まだ有効期限内です。サーバは毎回データベースを見ないので、そのトークンを添えた問い合わせは通ってしまいます。

この対策として、有効期限を15分など短めにします。または、取り消したトークンの一覧を別に持って毎回確認しますが、それをすると「データベースを見なくて済む」という利点が減ります。速さと取り消しやすさは、どちらかを選ぶ関係にあります。

認可段階的に複雑さに対応する

要するに：認可は「はい／いいえ」→「1つずつ並べる」→「役割で管理する」の順で、複雑さに応じて段階を上げます。

タカ
タカ師匠認証は「誰」、認可は「何」。どの対象に、どんな方法でアクセスできるか。組み合わせの数は膨大になり得る。
タカ

1

確認済みの名前を、管理者の表と照らし合わせる。

2

全員の身分を確認したうえで、管理者の表で管理者かどうかを確かめる。

🔎 具体例：役割で管理すると何が楽か

1つずつ並べる方式で、100人の利用者にそれぞれ10個の権限を設定していたとします。「編集者は下書きも見られるようにする」という変更が入ると、編集者にあたる30人分を1つずつ直すことになります。

役割で管理していれば、「編集者」という役割に権限を1つ足すだけで、その役割の30人全員に反映されます。新しく編集者が加わったときも、役割を1つ設定するだけで済みます。

✅ この項のまとめ

  • 認可 = 何ができるか
  • 段階: はい／いいえ → 1つずつ並べる → 役割で管理する
  • 書き込みは読み取りより厳しく

CORSどの画面からの呼び出しを許すか

要するに：CORS は、別の場所にある正規の画面との通信を許可する仕組みです。CORSMiddleware で設定します。

タカ
タカ師匠CORS は、別のサーバにある信頼できる画面と、この窓口との通信の話だ。画面も裏側も同じ場所にあるなら関係ない。けど最近は画面側と FastAPI の裏側が分かれていて、両者は同じオリジンを持たない。
タカ
タカ師匠オリジンは、通信の方式（http か https か）＋ ドメイン（例：google.com）＋ 入口番号（例：443、8000）の組み合わせだ。
タカ
タカ師匠裏側は、どうやって信頼できる画面と、そうでないものを見分けるか？ それが CORS だ。裏側が何を信頼するかを指定する。①オリジン、②動詞、③添え情報、④その設定を覚えておく時間。

オリジンとは

比べる相手オリジン同じか
基準https://ui.cryptids.com:443―
方式が違うhttp://ui.cryptids.com:443別のオリジン
ドメインが違うhttps://other.com:443別のオリジン
入口番号が違うhttps://ui.cryptids.com:8000別のオリジン
すべて同じhttps://ui.cryptids.com:443同じオリジン

信頼する画面を指定する設定です。

コードを見る（1行ずつ説明つき）
# 枠組み本体を取り込む。
from fastapi import FastAPI
# 別の場所からの呼び出しを扱う部品を取り込む。
from fastapi.middleware.cors import CORSMiddleware

# アプリ全体を作る。
app = FastAPI()

# くるむ処理として、別の場所からの呼び出しの設定を追加する。
app.add_middleware(
    CORSMiddleware,
    # 許可する呼び出し元の一覧。ここに書かれていない場所からの呼び出しは拒否される。
    allow_origins=["https://ui.cryptids.com"],
    # 許可する動詞。* はすべてという意味。必要なものだけに絞るほうが安全。
    allow_methods=["*"],
    # 許可する添え情報。同じく * はすべて。
    allow_headers=["*"],
)
# --- この設定で起きること ---
# ui.cryptids.com の画面からの呼び出しは通る。
# 別のドメインの画面からブラウザ経由で呼ぼうとすると、ブラウザ側で止められる。
タカ
タカ師匠これで、他のドメインからの直接の呼び出しは止められる。

🔎 具体例：設定しないとどうなるか

画面が https://ui.cryptids.com、窓口が https://api.cryptids.com にあるとします。CORS を設定していないと、ブラウザは「別のオリジンへの呼び出しは許可されていない」と判断し、画面側でエラーになります。窓口自体は動いているのに、画面からは使えません。

逆に allow_origins=["*"]（すべて許可）にすると、どんなサイトの画面からもこの窓口を呼べます。悪意のあるサイトが、訪問者のブラウザを通じてこの窓口を呼び出せてしまいます。必要な相手だけを書くのが基本です。

✅ この項のまとめ

  • CORS = 別の場所にある画面との通信の許可
  • オリジン = 方式 + ドメイン + 入口番号
  • CORSMiddleware で許可する相手を指定
  • 指定していない場所からの呼び出しは止められる

章末の理解度チェック全5問

第1問認証と認可

「認証」と「認可」の違いを、自分の言葉で説明してください。それぞれの典型的な実装例も挙げてください。

✅ 解答例
認証は「あなたは誰か」を確かめること。実装例は名前とパスワードでのログイン、トークン、OAuth2 など。認可は「あなたは何ができるか」を制御すること。実装例は「管理者だけが削除の窓口を使える」という はい／いいえ の判定、役割による制御、権限を1つずつ並べる方式など。認証は身元の確認、認可は権限の確認、と覚えると区別しやすい。
📝 採点ポイント
□ 認証 = 誰、認可 = 何 の枠組みで説明している
□ 認証の実装例（パスワード／トークン）を挙げている
□ 認可の実装例（役割／権限）を挙げている
第2問パスワードの保存の原則

利用者のパスワードを保存する際の原則を説明してください。なぜハッシュ化するのか、そのままの文字で保存してはいけない理由を含めてどうぞ。

✅ 解答例
パスワードは bcrypt などの方式でハッシュ化してから保存する。理由は、データベースの中身が外に出てしまった場合でも、ハッシュから元のパスワードを復元できないため、被害を小さくできるから。変換は一方向で、逆向きに戻せない。ログインのときは「入力されたパスワードを同じ方式で変換」して、保存済みのものと比べる。そのままの文字での保存は避ける（多くの人が複数のサイトで同じパスワードを使うため、被害が連鎖する）。
📝 採点ポイント
□ ハッシュ化（元に戻せない）に触れている
□ 情報が外に出たときの被害を小さくすることを理由として述べている
□ ログインのときの照合の方法を説明している
□ そのままの保存の危険性に触れている
第3問JWT の仕組み

JWT の構造と、確認の流れでの使われ方を説明してください。良い点と注意点も含めてどうぞ。

✅ 解答例
JWT はドットで区切られた3つの部分（先頭部・中身・署名）でできた文字列。各部分は、住所でも使える文字だけに変換された JSON。流れとしては、ログインに成功するとサーバが JWT を発行し、以降の問い合わせで Authorization: Bearer <jwt> という形で添える。サーバは読み取って利用者の情報を取り出す（データベースを探す必要がない）。良い点は速いこと、状態を持たなくてよいこと。注意点は、取り消しをその場で検出できないこと（有効期限を短くして対応）、トークンが漏れると期限内は使われてしまうこと。
📝 採点ポイント
□ 3つの部分の構造に触れている
□ Authorization: Bearer で運ぶことを述べている
□ 良い点（データベースを探さない、状態を持たない）に触れている
□ 注意点（取り消しの検出が難しい）に触れている
第4問CORS とは

CORS とは何ですか？ なぜ必要で、FastAPI ではどう設定しますか？

✅ 解答例
CORS は、異なるオリジン（通信の方式 + ドメイン + 入口番号）の間でのやり取りを制御する仕組み。画面側が https://ui.example.com、窓口が https://api.example.com のように分かれている今のやり方では、窓口が「どの画面からの呼び出しを許可するか」を指定する必要がある。FastAPI では CORSMiddleware を app.add_middleware() で追加し、allow_origins、allow_methods、allow_headers で条件を指定する。これで意図しない場所からの呼び出しを防げる。
📝 採点ポイント
□ オリジン（方式 + ドメイン + 入口番号）の定義に触れている
□ 画面と裏側が分かれている場合に必要、と説明している
□ CORSMiddleware を add_middleware で設定する方法に触れている
第5問認可の段階

単純な はい／いいえ による認可から、より複雑な認可へ進む3段階を、自分の言葉で説明してください。それぞれ使う場面も示してください。

✅ 解答例
①はい／いいえ：「管理者かどうか」だけを判定する単純な仕組み。小さなシステムや、権限が単純な場合に向く。②1つずつ並べる方式：権限の表と、利用者と権限の組み合わせの表で、利用者ごとに個別の権限を持たせる。読み取り専用の人、読み書きできる人、といった細かい制御が必要な場合に向く。③役割による制御：役割の表と、利用者と役割の組み合わせの表で、利用者を役割に結びつけ、役割に権限を結びつける。権限も利用者も多い、中規模以上のシステムに向く。
📝 採点ポイント
□ 3段階を順序立てて挙げている
□ それぞれの仕組みを簡潔に説明している
□ 使う場面を具体的に挙げている

# ハッシュ化の機能を取り込む。
from passlib.context import CryptContext

# bcrypt という方式を使う設定を用意する。
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# 同じ文字を2回変換してみる。
h1 = pwd_context.hash("mypassword")
h2 = pwd_context.hash("mypassword")
print(h1)
print(h2)
# --- 実行結果（値は毎回変わる） ---
# $2b$12$KIXQ4.../7oS9v...
# $2b$12$9aBcD.../3xY1z...
# 同じ文字なのに違う値になる。毎回ちがう「混ぜもの」が加えられるため。
# だから、同じパスワードを使っている人同士でも、保存された値は一致しない。

# それでも、照合はできる。
print(pwd_context.verify("mypassword", h1))
print(pwd_context.verify("wrongpass", h1))
# --- 実行結果 ---
# True
# False
